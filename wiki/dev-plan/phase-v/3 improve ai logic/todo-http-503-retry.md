# Задача на разработку: HTTP 503 — retry; прочие ошибки (в т.ч. 409) — пользователю
Обработать лимиты провайдеров единообразно для всех моделей: 503 ждать и повторять запрос; остальные ошибки (включая 409) сразу показать пользователю.

Зачем: бесплатные (и не только) модели отдают 503 при пиковой нагрузке; без retry цикл рвётся. 409 и прочее пользователь должен видеть, а не «тихий» обрыв.

Ожидаемый результат: общий retry на HTTP-слое AI-клиента (Gemini и openai-compat). 503: пауза и повтор, не больше настраиваемого числа раз (дефолт 20) из `projects/deck_gen_wasm/modules/conf/src/lib.rs`. Иной статус / сеть / 409 — без retry, `Err` доходит до warning-модалки как сейчас.

## Функциональные требования
- Логика **общая** для всех `kind`, платных и бесплатных. Не ветвить «только Gemini».
- **503:** подождать, повторить тот же POST. Попыток не больше константы (по умолчанию **20**). Константа — в `deck_gen_wasm_conf` (рядом с `pub mod ai` или отдельный knobs-блок в том же `lib.rs`). Пауза между попытками — тоже константа в этом файле (дефолт 3000 мс).
- Исчерпали попытки → ошибка пользователю (текст с кодом/телом, как сейчас формирует `post_json`).
- **Прочие ошибки, включая 409:** не ретраить; уведомить пользователя (существующий `warning` / `AlertModal` после `run_ai`). Не глотать. Текст можно оставить как HTTP body от провайдера.
- Успешный ответ после retry — обычный ход цикла, без отдельного UI «retried».
- Не менять семантику RPM/`throttle` (другая задача): retry живёт вокруг одного `post_json`, throttle раундов не переписывать.
- Не ретраить GitHub GET в `browser` (каталог/template). Только AI POST JSON.
- Детект 503: по HTTP статусу. Если `browser::post_json` сейчас прячет статус в строку `"HTTP {status}"` — либо парсить её в `ai/src/http.rs`, либо минимально отдать статус из browser **только если** строкового пути недостаточно. Не раздувать browser API.

## Scope
- `projects/deck_gen_wasm/modules/conf/src/lib.rs` — `HTTP_503_MAX_RETRIES` (20) и delay ms
- `projects/deck_gen_wasm/modules/ai/src/http.rs` — retry-обёртка `post_json`; **не** менять формулу `throttle`
- `projects/deck_gen_wasm/modules/ai/src/gemini.rs` / `openai.rs` — только если нужно вызывать обёртку вместо прямого `post_json` (лучше одна обёртка в `http.rs`, клиенты не дублируют retry)
- `projects/deck_gen_wasm/modules/browser/src/http.rs` — только если без статуса нельзя отличить 503
- native-тест на классификацию «retry vs fail» (строка/статус), без живой сети

Не трогать: json5 моделей, модалку ключа, `Workspace::clear`, тексты help/промптов, `max_rounds`.

`engine.rs` не обязателен: ошибка `complete` уже пишется в лог и возвращается в UI. Не дублировать notify в engine.

## Проверка корректности решения

**Тесты native**
- 503 → нужно ещё повторить, пока счётчик < max.
- 409 / 400 / 401 / сеть без статуса → сразу ошибка, без retry.
- Лимит 20 (или тестовый меньший max) → после N неудачных 503 — Err.

**Ручной смоук:** при живом 503 цикл не падает на первом же ответе (в логе/сети видны повторы); 409 или неверный ключ — одна попытка и модалка с текстом.

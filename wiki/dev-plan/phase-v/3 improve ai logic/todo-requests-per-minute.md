# Задача на разработку: Лимит запросов в минуту и `-1` = без ограничения
Заменить `requests_per_second` на лимит запросов **в минуту**. Значение `-1` у числовых настроек модели означает «без ограничения» (в том числе `max_rounds`).

Зачем: бесплатные модели лимитируют RPM, а не RPS; `-1` должен явно отключать потолок.

Ожидаемый результат: в json5 поле `requests_per_minute`; пауза между HTTP-вызовами модели не чаще чем `60с / N`; в скользящем окне 60с не больше `N` вызовов. `N == -1` или поле опущено → троттлинга нет. `max_rounds: -1` → цикл не режется дефолтным 12.

## Функциональные требования

### Поле конфига
- Было: `requests_per_second`. Стало: `requests_per_minute`. Старое имя не поддерживать.
- Предустановки bundled json5: заменить ключ (текущее `1` оставить как `requests_per_minute: 1`, не выдумывать другое число).
- Документация в bundled `ai-help*` (текущий файл или уже en/ru). **Не** переносить help в `help/` и **не** добавлять `api-key-hosting` в этой задаче.

### `-1` = нет ограничения
Верно для **всех числовых** показателей модели, которые уже есть (`requests_per_minute`, `max_rounds`, и любых других числовых в `ModelConf`, если появятся в том же парсере).
- `-1` → без лимита (троттлинг выкл; `max_rounds` не останавливает цикл по счётчику раундов).
- Поле отсутствует → как сейчас разумный дефолт в коде (`max_rounds` default 12; RPM отсутствует → без троттлинга).
- `0` не использовать как «без лимита». Не считать `0` валидным RPM (игнорировать / как omit — не плодить третью семантику без нужды).

### Троттлинг при `N > 0`
Ненулевой RPM влияет **и** на частоту, **и** на сколько вызовов можно сделать за минуту:
1. Частота: не чаще чем `60_000 мс / N` между запросами к модели.
2. Квота: не больше `N` запросов за любые 60 секунд; если окно заполнено — ждать, пока слот освободится.

Первый запрос раунда/цикла может идти сразу, если квота позволяет. Троттлить HTTP к LLM (`complete`), не tool-исполнение на VFS.

Бесконечный цикл при `max_rounds == -1` не страховать отдельным скрытым потолком.

### Не входит
- Retry 503, разбор 409 — другая задача. Функцию `throttle` можно менять; обёртку retry вокруг `post_json` не писать.
- UI модалки, `api-key-hosting`, help-пути VFS.

## Проверка корректности решения

**Тесты native**
- Парсинг: `requests_per_minute: 1` → Some(1); поле отсутствует → нет троттлинга; `-1` → нет троттлинга; `max_rounds: -1` не подменяется на 12; `max_rounds` omit → 12.
- Старое имя `requests_per_second` не читается как RPM.
- Интервал: для `N=2` пауза ≥ 30000 мс (тест формулы/хелпера без реального sleep на 30с — считать delay из N).
- Квота: хелпер «можно ли ещё запрос» при N=1 и одной отметке в окне 60с → нельзя.

**Ручной смоук:** модель с `requests_per_minute: 1`, короткий цикл из нескольких round — паузы порядка минуты, не секунды.

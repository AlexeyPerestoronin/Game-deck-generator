# Роль
Ты профессиональный разработчик (`см. WiKi/harness/roles/senior-developer.md`).

# Задача
По факту выполнения задачи `WiKi/dev-plan/phase-v/2 implement ai abilities/todo.md` в процессе тестирования были обнаружен моменты которые доработать.

Необходимо сформировать задачи на доработку по следующим аспектам:

## api key entering
В модальном диалоговом окне использования ai необходимо добавить поле ввода api-ключа, который будет использоваться для запроса.

Моменты:
- введённый ключ имеет приоритет над тем, который записан в конфигурационном файле
- поле должно скрывать символы, но показывать при нажатии на значок глаза (как в полях для ввода паролей)
- данное поле должно быть расположено на одной линии с кнопками `отмена` и `запустить`, будучи самым первой (крайним слева);

## api key generation help
В модальном окне использования ai, необходимо добавить кнопку `API key request` (на одной линии справа от выпадающего спика выбора модели) при нажатии на которую для пользователя будет открываться новая вкладка в браузере с url-сайта где необходимо получить api ключи в зависимости от поставщика модели.

Данный url-адрес должен быть частью конфигурационного файла модели с ключом `api-key-hosting`.
Указанный ключ может быть опциональным и в случае его отсутствия кнопка не должна появляться в модальном окне.

## clear workspace
При очищении рабочей области должны удаляться не все файлы а только файлы игр (всё то, что находится в папке games).

## request per seconds to request per minute
Сейчас в конфигурационных файлах для моделей есть ограничение на количество запросов в секунду (`requests_per_second: 1`) → необходимо изменить эту логику на ограничение количества запросов в минуту.

Моменты:
- если показатель равен `-1` значит ограничения отсутствуют (это же должно быть верно для всех прочих числовых показателей в настройках, например, `max_round`);
- ненулевой показатель количества запросов в минуту должен влиять не только на то, сколько всего запросов можно совершить, но и на частоту запросов, которое должно быть не чаще чем `60сек / <количество запросов в минуту>`.

## fail 409 and 503
Бесплатные модели имеют лимиты на использование (error 409) + требовательный к количеству запросов в минуту (error 503).
```
https://generativelanguage.googleapis.com/v1beta/models/gemini-3.8-flash:generateContent?key=???: HTTP 503: {
  "error": {
    "code": 503,
    "message": "This model is currently experiencing high demand. Spikes in demand are usually temporary. Please try again later.",
    "status": "UNAVAILABLE"
  }
}
```
Эти ограничения необходимо учитывать и корректно обрабатывать:
- error 503: ждать некоторое время после чего повторять попытку запроса (не больше 20 раз; числовой параметр должен быть настраиваемым через `projects\deck_gen_wasm\modules\conf\src\lib.rs`);
- прочие ошибки включая 409 → уведомлять пользователя.

Логика обработки должна быть общей для всех моделей не зависимо от того бесплатные они или платные (могу ли возникнуть подобные исключения или нет).

## ai-help.md
Файл `deck_gen_wasm\modules\ai\bundled\ai-help.md` должен получить локализацию `ai-help-ru.md` и `ai-help-en.md`.
В зависимости от локали должен загружаться соответствующий файл.
При смене локали нет необходимо в специальной логике, кроме той, что если нет файла для локали, то его надо загрузить (прочие файлы локали пусть остаются, если загружены).

Дополнения:
1. Аналогичным образом необходимо локализовать `game-help.md` и `user-help.md`.
2. Пусть все help файлы будут храниться в коневой папке `help` в LFS.

## templates to file
Шаблоны запросов, которые сейчас записаны напрямую в коде (см. `request_text` и `system_prompt` в `projects\deck_gen_wasm\modules\ai\src\engine.rs`) необходимо выделить в отдельные файлы:
1. `create-game-pt-<ru|en>.md` - для создания новой игры.
2. `edit-game-<ru|en>.md` - для редактирования существующей игры.

Данные файл необходимо поместить в `deck_gen_wasm\modules\ai\bundled`

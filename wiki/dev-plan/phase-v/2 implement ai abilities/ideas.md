# AI abilities для `deck_gen_wasm` — анализ и предложения

Только анализ, код не менялся.

## 1. Что уже есть в коде

Приложение — **serverless CSR WASM** (Leptos 0.8). Сервера нет: HTTP уходит из браузера (`gloo-net`), состояние — in-memory VFS + localStorage/IndexedDB.

```
main → ui → workspace → fs (Vfs)
                     → template (GitHub, user-help)
                     → persist / import / export
                     → browser (GET text/bytes)
conf = compile-time константы
```

Существующие опоры для AI:

| Нужно AI | Уже есть |
|---|---|
| Смотреть дерево игр | `Vfs::{children, visit_entries, is_dir, is_file, exists, read_file}` |
| Создавать/править файлы | `mkdir, create_file, put_file, write_file, remove, rename` |
| Не блокировать UI | `Workspace::{loading, progress, try_begin_async, spawn_local}` |
| Правила игры в VFS | паттерн `ensure_user_help` / `template::help` (`user-help.md` в корень, если нет) |
| Скачать README с GitHub | `browser::fetch_text` + `template::github::raw_url_for` |
| Изолированный модуль | тот же стиль, что `fs`, `template`, `persist` (без Leptos) |
| Конфиг списком | `locale/dict.json5` через `include_str` + `json5` |
| Выбор игры/колоды | `local_games()`, explorer `selected`, структура `games/<id>/{game.json5,vars,decks,views}` |
| Мультимодель в Settings | сейчас только theme/locale/feedback — место для ключа и модели |

Ограничения WASM/браузера, которые режут дизайн:

1. **CORS.** Сейчас HTTP — только GET. LLM — POST JSON. Gemini часто отвечает из браузера с `?key=`; DeepSeek (`api.deepseek.com`) и xAI/Grok (`api.x.ai`) CORS, как правило, **не** отдают. Без прокси два провайдера могут быть недоступны.
2. **Ключи.** Сервера нет → ключ только у пользователя, localStorage, уходит лишь к выбранному провайдеру.
3. **Нет потоков.** Агент — `spawn_local`, один `loading` (уже запрещает параллельные prepare/zip).
4. **Токены free-tier.** Нельзя скармливать весь VFS. Сначала дерево, потом точечное чтение.
5. **«Бесплатные модели».** Реальный free-tier API стабилен у **Gemini**. Официальные API DeepSeek и Grok обычно платные (дешёвые / с триалом). Это надо явно зафиксировать в конфиге (`free: true`) и не регистрировать платные id.

Карты в движке — это **не картинки**, а `views/*.html` + `*.scss` + `decks/**/data.json5` (`view.face` / `view.back`). AI должен править эти файлы, а не генерировать PNG (если отдельно не решим иначе).

## 2. Общий каркас (для всех вариантов)

Без этого ни один вариант не закрывает ТЗ.

### 2.1 Модуль backend: `modules/ai` (`deck_gen_wasm_ai`)

Изолированный crate. **Не** зависит от `ui`, `workspace`, `leptos`.

Зависимости: `fs`, `conf`, `browser` (HTTP), `serde`/`json5`.

Публичный API (черновик, KISS):

```text
AiEngine
  from_config() -> Self
  models() -> &[ModelSpec]          // только free: true
  set_model(id)
  set_api_key(provider, key)        // ключ НЕ в конфиге
  run(req: AiRequest, vfs: &Vfs) -> AiOutcome

AiRequest
  Chat { messages, scope }
  CreateGame { prompt }
  EditDeck { game, deck?, prompt }
  EditFaces { game, deck, side: Face|Back|Both, prompt }

AiOutcome
  messages: ответы ассистента
  ops: Vec<VfsOp>                   // mkdir / write  (опционально delete)
  usage: токены / rounds
```

Провайдеры за трейтом `LlmClient` (chat ± tool-calling ± JSON-mode):

- `GeminiClient`
- `DeepSeekClient` (OpenAI-compatible)
- `GrokClient` (OpenAI-compatible, xAI)

Переключение модели — смена `ModelSpec` в `AiEngine`, UI только передаёт id.

`VfsOp` возвращаются наружу: модуль **не** пишет в `RwSignal`. `workspace` делает `flush_draft` → применяет ops → `vfs.set`. Так backend тестируется нативным `Vfs` без WASM.

Песочница внутри модуля (не в UI):

- писать только под `games/`
- не трогать `_autogenerated/`
- только UTF-8 текст, расширения из `conf::ext` / `IMPORT_TEXT`
- капы: max rounds, max chars/file, max files/turn, max depth дерева
- path traversal уже режет `Vfs::split_path`

В `deck_gen_wasm_browser` добавить `post_json` (сейчас только GET). Альтернатива — HTTP внутри `ai`; хуже по DRY.

### 2.2 Конфиг моделей — файл, не код

По образцу `locale/dict.json5`: `modules/ai/models.json5` + `include_str` на сборке.

Ключи **не** хранить здесь. Пример:

```json5
{
  default: "gemini-2.0-flash",
  limits: { max_rounds: 12, max_file_chars: 80000, max_files_per_turn: 16 },
  providers: {
    gemini: {
      kind: "gemini",
      base_url: "https://generativelanguage.googleapis.com/v1beta",
      auth: "query-key",          // ?key=
      cors: "browser",
      models: [
        { id: "gemini-2.0-flash",      label: "Gemini 2.0 Flash",      free: true },
        { id: "gemini-2.0-flash-lite", label: "Gemini 2.0 Flash-Lite", free: true }
      ]
    },
    deepseek: {
      kind: "openai-compat",
      base_url: "https://api.deepseek.com",
      auth: "bearer",
      cors: "blocked",            // нужен proxy_url пользователя
      models: [
        { id: "deepseek-chat", label: "DeepSeek Chat", free: true }
      ]
    },
    grok: {
      kind: "openai-compat",
      base_url: "https://api.x.ai/v1",
      auth: "bearer",
      cors: "blocked",
      models: [
        { id: "grok-3-mini", label: "Grok 3 Mini", free: true }
      ]
    }
  }
}
```

В рантайм попадают только `free: true`. `cors: "blocked"` → в UI поле «CORS proxy» (пустое по умолчанию). `base_url` / model id правятся без рефакторинга клиентов.

Персист пользователя (не git): `localStorage`

- `deck_gen_wasm.ai.model`
- `deck_gen_wasm.ai.keys` (map provider → key)
- `deck_gen_wasm.ai.proxy` (опционально)

По аналогии с `conf::session::LOCALE_KEY`.

Константы в `conf` (пути, URL README, storage keys, лимиты-дубли если нужно UI). Сами модели — в json5.

### 2.3 README правил в корень VFS

Как `user-help.md`:

- URL: `https://raw.githubusercontent.com/AlexeyPerestoronin/Deck-Games/master/README.md`
- путь: `README.md` в корне VFS
- класть при загрузке/перезагрузке приложения, **если файла ещё нет**
- не затирать ручные правки
- сеть упала → статус, AI стартует с урезанным system prompt (и/или bundled fallback)

Логично расширить `template` (+ `conf::rules`), не пихать HTTP в `ai`. `ai` только **читает** `README.md` из VFS как правила.

Вызов: рядом с `workspace.ensure_user_help()` в `App` (async fetch, как каталог).

### 2.4 Связка с workspace (тонкий слой)

`workspace` остаётся оркестратором:

1. `flush_draft`
2. снять snapshot `Vfs`
3. `AiEngine::run`
4. показать/применить `ops`
5. `loading` + progress ray
6. статус / warning modal

UI не знает про Gemini vs Grok.

## 3. Предложения

Ось различий — **как модель получает контекст и как пишет в VFS**. Транспорт моделей и README — общие.

### Вариант A — Агент с tool-calling (свободный чат)

**Backend.** Цикл: user → LLM (tools) → исполнить tool на снимке Vfs → снова LLM, пока `end` или лимит rounds.

Tools:

- `list_dir(path)`
- `tree(path, depth)`
- `read_file(path)`
- `write_file(path, content)`  → копит `VfsOp`, не коммитит в signal
- `mkdir(path)`

System: README + краткий layout (`game.json5`, `decks/`, `views/`, правило `{game-id}.{path.from.decks}`).

Три сценария ТЗ = три стартовых system/user шаблона, тот же цикл.

**Frontend.** Новый `SidebarMode::Ai` + кнопка activity bar.

- лента чата, input, Stop
- селектор модели, поля ключей (Settings или шапка панели)
- чипы: «Новая игра» / «Колода» / «Лицо/рубашка» (подставляют шаблон и scope из selection)
- дерево обновляется после apply
- опционально: клик по пути в ответе → открыть вкладку

**Плюсы:** один механизм на все будущие запросы; экономит токены (сам читает нужное).  
**Минусы:** непредсказуемые правки; tool-calling у free-моделей разный (Gemini ок, часть mini — слабее); сложнее отладка.

### Вариант B — Три структурированных сценария (JSON, без агента)

**Backend.** Нет tools. Один (редко два) запроса. В контекст кладётся заранее выбранное.

1. **Новая игра:** дерево `new-game` (или эталон) + README + prompt → JSON `{ files: [{path, content}] }` под `games/<new-id>/`.
2. **Колода:** `data.json5` колоды + связанные `vars/` → JSON патч/полный файл.
3. **Стороны:** `view.face` / `view.back` + html/scss → новые шаблоны.

Парсер JSON (в т.ч. из ````json` fence). Валидация путей той же песочницей. Нет round-trips.

**Frontend.** Не чат, а мастер:

- шаг 1: сценарий
- шаг 2: игра/колода/сторона (если не из explorer)
- шаг 3: prompt
- шаг 4: список файлов, Accept / Discard

Чат не обязателен. Модель — в Settings.

**Плюсы:** предсказуемо, дёшево, проще тестировать, лучше на слабых free-моделях.  
**Минусы:** «поправь ещё вот это» = новый прогон; легко промахнуться с контекстом; не общий агент.

### Вариант C — Plan → Diff → Apply (рекомендуемый гибрид)

**Backend.** Движок как в A (tools **или** JSON-план), но наружу всегда:

```text
AiOutcome { notes, ops: [Write/Mkdir], preview_diff }
```

Коммит только после `apply`. Два прохода: (1) план списка путей, (2) содержимое. На free-моделях без надёжных tools — деградация в JSON как в B.

Три сценария — пресеты: фиксированный scope (новая папка / одна колода / views колоды) + запрет писать вне scope.

**Frontend.** Панель AI как в A, плюс:

- экран диффа (path list, раскрыть содержимое, Uncheck файла)
- Apply selected / Reject
- пресеты сценариев над чатом
- после Apply — статус «N files», можно сразу Prepare HTML

**Плюсы:** закрывает ТЗ; безопасен для уже загруженных игр; изолированный API; три сценария не разъезжаются с чатом.  
**Минусы:** больше UI, чем B; два шага вместо «магии».

### Вариант D — Single-shot dump (минимальный прототип)

**Backend.** Склеить README + `tree` + все текстовые файлы scope (кап по символам) → один `complete` → распарсить «файлы» из markdown. Без tools, без JSON-schema.

**Frontend.** Одно поле prompt + кнопка. Модель в Settings. Результат сразу в VFS или confirm списком путей.

**Плюсы:**最快ший путь проверить ключи/CORS/модели.  
**Минусы:** не масштабируется; взрывает free-quota; слабый контроль структуры; как продукт — тупик.

## 4. Сравнительная таблица

| Критерий | A Агент | B Сценарии | C Plan/Diff | D Dump |
|---|---|---|---|---|
| Новая игра / колода / стороны | да, пресетами | да, ядро | да, пресеты + scope | слабо, «как получится» |
| Изолированный backend API | да | да | да | да, слишком тонкий |
| Мультимодель + json5 | да | да | да | да |
| Предсказуемость VFS | низкая | высокая | высокая (confirm) | низкая |
| Токены / free-tier | средние | низкие | средние | высокие |
| Сложность backend | высокая | средняя | высокая | низкая |
| Сложность UI | средняя | средняя | выше средней | низкая |
| UX «поправь ещё» | отличный | слабый | хороший | слабый |
| Безопасность правок | слабая без confirm | хорошая | лучшая | плохая |
| Слабые free-модели | риск | лучше | есть fallback JSON | риск |
| Расширять новыми командами | легко | каждый раз новый сценарий | легко | никак |
| Соответствие YAGNI | средний overkill | впритык к ТЗ | чуть больше B, закрывает риски | слишком мало |

Оценка трудозатрат (порядок, не смета): D ≪ B < A < C, причём C = A + diff UI **или** B + diff UI.

## 5. Рекомендация

**Вариант C**, внедрять слоями (чтобы не делать C целиком в одном ПРе):

1. **Слой 0 — инфраструктура (обязательный ТЗ):** crate `ai`, `models.json5`, трейт провайдеров, Gemini+DeepSeek+Grok, ключи, переключение модели, `post_json`, установка `README.md`, песочница путей. Пока без «умного» цикла — `complete` + парсинг.
2. **Слой 1 — продукт минимум:** три пресета как в B (JSON files) + экран Apply/Reject. Это уже закрывает 3 пункта цели.
3. **Слой 2 — агент:** tools + чат на том же `AiOutcome.ops`. Пресеты остаются сокращением первого сообщения и scope.
4. **Слой 3 (по необходимости):** стриминг, persist истории, картинки для арт-рубашек.

Почему не сразу A: без diff легко испортить колоду; tool-calling на free Grok/DeepSeek неоднороден.  
Почему не остановиться на B: чат «допиши рубашку в том же стиле» всё равно понадобится. C даёт один `AiOutcome` на оба UX.

Дефолт модели: **Gemini Flash** (`cors: browser`, реальный free-tier). DeepSeek/Grok в списке, но UI честно показывает «нужен ключ + возможно proxy».

## 6. Frontend: процесс пользователя (для C)

```
Activity bar [AI]
  → sidebar «AI»
      [модель ▾] [ключ…] [proxy…]
      пресеты: Новая игра | Колода | Лицо/рубашка
      scope: из explorer / Games / явный select
      история сообщений
      textarea + Send / Stop
      ── после ответа ──
      список ops [✓] path
      [Apply] [Reject]
Explorer/editor обновляются стандартным vfs signal (autosave как сейчас)
Дальше пользователь жмёт Prepare HTML / PDF — AI это не вызывает
```

Settings: пункт «AI…» (модель, ключи, proxy) — дубль шапки панели, чтобы ключ жил и без открытого чата.

Локализация: новые ключи в `locale/dict.json5` (EN/RU), как остальные кнопки.

Иконка: новый activity-button по образцу Games/Explorer.

Пока `loading` — те же disable, что у Prepare/ZIP.

## 7. Риски и как резать

| Риск | Что делать |
|---|---|
| CORS DeepSeek/Grok | `cors` в json5 + опциональный `proxy_url`; Gemini — дефолт |
| Нет настоящего free API у Grok/DeepSeek | в конфиг только то, что подтверждаем; иначе скрыть `free: false` |
| Утечка ключа | только localStorage, не логировать, не класть в VFS/ZIP |
| Порча игр | sandbox + confirm + не писать `_autogenerated` |
| Квота Gemini | лимиты rounds/chars; кнопка Stop; не слать бинари |
| README недоступен | bundled fallback / работа без него с warning |
| WASM size | не тащить ML-рантаймы; HTTP+JSON хватит |
| JSON5 игр vs JSON модели | модель пишет json5-совместимый текст; не прогонять через serde_json, если не нужно |

AI **не** вызывает `prepare_html` / `prepare_pdf` в v1 (длинно, PDF-движок, легко упереться в `loading`). Пользователь жмёт кнопки сам.

## 8. Открытые вопросы

Нужны ответы до реализации слоя 0–1:

1. **Ключи.** Только пользовательские, или будет общий прокси с нашим ключом? (при serverless — только пользовательские.)
2. **CORS.** Допустим ли user-provided proxy URL? Или DeepSeek/Grok в v1 показываем, но «может не завестись из браузера»?
3. **Free.** Какие **точные** model id считать бесплатными? Если у DeepSeek/Grok нет free API — оставляем в списке или выкидываем до появления tier?
4. **Картинки.** Стороны карт = html/scss, или ещё генерация PNG в `views/`?
5. **Apply.** Всегда confirm (C) или автозапись с Undo?
6. **README.** Только если нет файла, или refresh с GitHub при каждой загрузке приложения (как в формулировке «при загрузке/перезагрузке, если его там ещё нет» — текущее чтение: **не затирать**)?
7. **История чата.** Сессия в памяти или persist? (YAGNI: память.)
8. **Удаление файлов агентом.** Разрешить `remove` или только mkdir/write?

Пока предполагаемые дефолты, если не ответят: пользовательские ключи; proxy опционален; в json5 только явно free; стороны = html/scss; confirm Apply; README не затирать; история не персистить; delete запрещён в v1.

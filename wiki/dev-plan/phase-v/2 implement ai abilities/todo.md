# Задача на разработку: AI abilities для `deck_gen_wasm`
Добавить в serverless CSR WASM-приложение возможность создавать и править карточные игры через AI-агента: новый запрос → цикл инструментов по VFS → лог в Markdown.

Зачем: пользователь должен уметь (1) создать полностью новую игру, (2) править файлы конкретной игры (колода, лицо/рубашка и любые другие исходники), не зная наизусть устройство `games/<id>/`. Правила игры агент читает из `game-help.md` в корне VFS. Модели и ключи — файлы в `ai-models/`, без сервера и без ключей в коде.

Ожидаемый результат: изолированный crate `deck_gen_wasm_ai` + тонкая связка в `workspace` + два UI-входа (кнопка в панели Local games и кнопка `ai edit` в activity bar). После запроса агент сам пишет файлы в VFS (без confirm/diff/чата), проверяет себя через `prepare_html`, а ход работы можно открыть в preview как `ai-models/log/<date-time>-<model-name>.md`.

Исходные документы: `planning.md` (цель), `ideas.md` (решения). Ниже — **только принятое**. Отклонённое перечислено отдельно и **не реализовывать**.

## Что принято и что отклонено

### Принято (с корректировками из `ideas.md`)
- Backend — отдельный модуль с изолированным API, без `ui` / `workspace` / `leptos`.
- Мультимодель: Gemini / DeepSeek / Grok и любые пользовательские; бесплатные — только предустановки.
- Настройки модели — **отдельный json5 на каждую модель** в корне VFS: `ai-models/<id>.json5`.
- API-ключ — поле в этом json5 (не localStorage, не compile-time).
- `AiEngine`: только `from_conf` и `run_loop`. Нет `models` / `set_model` / `set_api_key` / `run`.
- Нет `AiOutcome`. Наблюдаемость — markdown-лог в VFS, пишется **в процессе** цикла.
- Запросы только:
  - `CreateGame { prompt }`
  - `EditGame { game, file, prompt }`
- Агент с tool-calling: полный доступ к VFS на чтение и на запись, кроме write в `_autogenerated/`.
- Обязательный инструмент `prepare-html` (проверка правок). PDF/PNG агенту не нужны.
- Apply сразу (небезопасный режим, без экрана диффа и без Undo).
- `game-help.md` в корне VFS по той же логике, что `user-help.md`. README с GitHub **не** качать.
- `workspace` — оркестратор: `flush_draft` → снимок VFS → `run_loop` → записать VFS → `loading`/progress/status.
- CORS-прокси допустим (поле в конфиге модели).
- Опциональный лимит запросов в секунду в конфиге модели. Платные/бесплатные модели не разделять.
- Frontend: **не чат**. Один запрос → цикл до завершения → лог.
- Кнопка «create new game with AI» в Local games (под «Load Local Games»).
- Кнопка `ai edit` в activity bar сразу под split preview.

### Отклонено (не делать)
- Варианты A/B/C/D из §3 `ideas.md` целиком: свободный чат, мастер из трёх сценариев, Plan→Diff→Apply, single-shot dump.
- `SidebarMode::Ai`, лента чата, Stop, чипы сценариев, экран диффа, Accept/Discard по файлам.
- Один `models.json5` на все модели; compile-time список как единственный источник.
- Ключи/модель/proxy в `localStorage` (`deck_gen_wasm.ai.*`).
- Методы `AiEngine::{models,set_model,set_api_key,run}` и тип `AiOutcome`.
- Только `free: true` модели в рантайме; поле `free` в конфиге.
- Загрузка `README.md` с `Deck-Games`.
- Confirm перед записью; история чата; генерация PNG/PDF агентом.
- Ограничение «писать только под `games/`». Единственный write-запрет — `_autogenerated/`.
- Расширение Settings (theme/locale/feedback) полями ключа и модели.

## Функциональные требования

### 1. Модуль backend `projects/deck_gen_wasm/modules/ai` (`deck_gen_wasm_ai`)

Изолированный crate в том же стиле, что `fs` / `template` / `persist`.

**Зависимости:** `deck_gen_wasm_fs`, `deck_gen_wasm_conf`, `deck_gen_wasm_browser`, `serde`/`json5`, `deck_gen` (только ради инструмента `prepare_html` + `VfsFs`).  
**Не зависит от:** `deck_gen_wasm_ui`, `deck_gen_wasm_workspace`, `leptos`.

Публичный API — ровно два метода:

```text
AiEngine
  from_conf(vfs, model_path) -> Result<Self, String>
  run_loop(req: AiRequest, vfs: &mut Vfs) -> Result<(), String>   // async

AiRequest
  CreateGame { prompt }
  EditGame { game, file, prompt }
```

- `from_conf` читает **один** json5 по `model_path` (например `ai-models/gemini-2.0-flash.json5`) и готовит клиент. Список моделей UI строит сам обходом `ai-models/*.json5` — метод `models()` не нужен.
- `run_loop` мутирует переданный `Vfs` (файлы игры + лог). Наружу не возвращает ops/diff. Ошибка сети/ключа/парсинга — `Err(String)`; частичные правки в `vfs` допустимы (небезопасный режим).
- Цикл наблюдаем: лог дописывается в VFS **на каждом шаге**, не только в конце.

Провайдеры за узким внутренним трейтом (chat + tool-calling), без утечки в публичный API:

- `kind: "gemini"` — Gemini REST (`?key=` или как требует `auth`).
- `kind: "openai-compat"` — DeepSeek / Grok / пользовательские OpenAI-compatible.

KISS: два клиента, без лишних абстракций «на будущее».

### 2. Конфиг модели — файл в VFS, не код

Папка **корня VFS**: `ai-models/`.

| Путь | Назначение |
|---|---|
| `ai-models/<id>.json5` | одна модель = один файл |
| `ai-models/ai-help.md` | как писать конфиги и как ими пользоваться |
| `ai-models/log/<date-time>-<model-name>.md` | лог одного `run_loop` |

Пользователь может добавить свой json5 — модель появляется в селекторе без пересборки.

Схема json5 (поля, которые должны парситься; лишние игнорировать):

```json5
{
  id: "gemini-2.0-flash",          // должно совпадать с именем файла без .json5
  label: "Gemini 2.0 Flash",
  kind: "gemini",                  // "gemini" | "openai-compat"
  base_url: "https://generativelanguage.googleapis.com/v1beta",
  auth: "query-key",               // "query-key" | "bearer"
  api_key: "",                     // пользователь вписывает сам
  cors: "browser",                 // "browser" | "blocked"
  proxy_url: "",                   // CORS-прокси; пусто = прямой запрос
  requests_per_second: 1,          // опционально; нет поля = без троттлинга
  max_rounds: 12                   // опционально; нет поля = разумный дефолт в коде, чтобы цикл не был бесконечным
}
```

- Аутентификация **только** через `api_key` в этом файле.
- Если `cors: "blocked"` и `proxy_url` пуст — `from_conf`/`run_loop` возвращает понятную ошибку (модель из браузера, скорее всего, недоступна).
- Если `proxy_url` задан — HTTP идёт через него (user-provided proxy).
- Пустой `api_key` — ошибка до первого сетевого вызова, текст для UI.

Предустановленные файлы (ключ оставить пустым):

- `ai-models/gemini-2.0-flash.json5` — Gemini 2.0 Flash, `kind: gemini`, `auth: query-key`, `cors: browser`
- `ai-models/gemini-2.0-flash-lite.json5` — то же, Flash-Lite
- `ai-models/deepseek-chat.json5` — `kind: openai-compat`, `base_url: https://api.deepseek.com`, `auth: bearer`, `cors: blocked`
- `ai-models/grok-3-mini.json5` — `kind: openai-compat`, `base_url: https://api.x.ai/v1`, `auth: bearer`, `cors: blocked`

Бандлятся в crate (`include_str`) и копируются в VFS при загрузке приложения, **если файла ещё нет**. Ручные правки (в т.ч. вписанный ключ) не затирать. Если вместо json5 лежит HTML-shell приложения — переустановить, по той же эвристике, что `user-help.md`.

`ai-help.md` — bundled инструкция: какие поля обязательны, примеры Gemini и openai-compat, куда писать ключ, зачем `proxy_url`, что логи лежат в `ai-models/log/`. Ставить в VFS, если нет.

Константы путей — в `deck_gen_wasm_conf` (как `conf::help::PATH`). Сами модели — не в `conf`.

### 3. `game-help.md` (правила для агента)

Не качать README с GitHub.

Файл `game-help.md` в **корне VFS**, логика как у `user-help.md`:

- bundled текст в `modules/template` (или рядом, если так чище по SRP);
- `needs_install` / `install`, если нет файла или тело — HTML-shell;
- не затирать правки пользователя;
- вызов рядом с `workspace.ensure_user_help()` при старте `App`.

Содержимое — рабочая инструкция по устройству игры (layout `games/<id>/`, `game.json5`, `vars/`, `decks/**/data.json5`, `views/*.html|scss`, правило имени колоды `{game-id}.{path.from.decks}`, что HTML карт собирается `prepare_html` в `_autogenerated/`, что туда руками не писать). Текст может быть черновым — его поправят отдельно.

Агент в system prompt **читает** `game-help.md` из VFS. HTTP за правилами не ходит. `ai` не качает help — только читает.

При старте также: `ensure` папки `ai-models/` + дефолтные json5 + `ai-help.md` (см. §2).

### 4. Агент: `run_loop`, инструменты, лог

Цикл: user request → LLM (tools) → исполнить tool на `&mut Vfs` → снова LLM, пока модель не завершит или `max_rounds`.

Инструменты (полный доступ к VFS, кроме write в autogen):

| Tool | Поведение |
|---|---|
| `ls(path)` | дети директории (имя + file/dir) |
| `read_file(path)` | UTF-8 тело; нет/бинарник — ошибка tool |
| `write_file(path, content)` | создать/перезаписать UTF-8; parents по необходимости |
| `mkdir(path)` | создать папку |
| `remove(path)` | удалить файл или дерево |
| `prepare_html` | `deck_gen::prepare_html` над VFS (через `VfsFs`), как в workspace, без PDF |

Песочница **внутри** модуля `ai`, не в UI:

- **write/mkdir/remove запрещены**, если путь равен `_autogenerated` или лежит под ним (в любой игре). Чтение `_autogenerated` разрешено.
- `prepare_html` **имеет право** писать в `_autogenerated/` — это единственный легальный способ создать autogen.
- Path traversal уже режет `Vfs::split_path`; отдельно не дублировать, кроме явной проверки `_autogenerated`.
- После правок исходников модель **должна** вызывать `prepare_html` и по результату чинить ошибки. Зафиксировать это в system prompt. PDF/PNG в промпт не включать.

Стартовый user/system зависит от `AiRequest`:

- `CreateGame { prompt }` — создать новую игру под `games/<id>/` по `game-help.md` и промпту.
- `EditGame { game, file, prompt }` — `game` = корень игры (`games/poker`), `file` = путь целевого файла. Агент может **читать** соседние файлы игры, но задача сформулирована про этот файл.

Лог: `ai-models/log/<date-time>-<model-name>.md`.

- Имя безопасное для VFS (без `:` в дате, например `2026-04-06T12-00-00-gemini-2.0-flash.md`).
- Markdown, чтобы открыть Preview.
- Писать **по ходу**: запрос пользователя, reasoning (если провайдер отдал), вызовы инструментов с аргументами, результаты tools (обрезать огромные тела), финальный текст ассистента, ошибка обрыва.
- Файл создаётся в начале `run_loop`, дописывается каждый раунд.

HTTP: в `deck_gen_wasm_browser` добавить POST JSON (сейчас только GET в `http.rs`). Клиенты `ai` ходят через `browser`, не дублируют `gloo-net`. Учитывать `proxy_url` и `requests_per_second`.

### 5. Связка с `workspace` (тонкий слой)

`workspace` остаётся оркестратором. UI не знает Gemini vs Grok.

Последовательность одного запроса:

1. Проверить, что нет чужого `loading` (`try_begin_async`).
2. `flush_draft`.
3. Снять snapshot `Vfs`.
4. `AiEngine::from_conf(vfs, model_path)?`
5. Открыть (или сразу создать) лог-файл и показать его Preview-вкладкой — пользователь наблюдает процесс.
6. `run_loop(req, &mut vfs).await`. Пока цикл идёт — обновлять signal VFS достаточно часто, чтобы preview лога жил (после каждого раунда или через колбэк из `ai`; не обязательно каждый байт).
7. По успеху: `vfs.set`, status. По ошибке: warning modal + то, что уже успели записать.
8. `finish_async`. Progress ray — как у prepare/load.

UI не применяет ops поштучно и не показывает diff. Confirm нет.

После цикла дерево/вкладки сами подхватят новый VFS (как после `add_new_game`).

### 6. Frontend

Чата нет. Два входа = два варианта `AiRequest`.

Общее для обоих модальных окон:

- Заголовок, textarea промпта, селектор модели (файлы `ai-models/*.json5` кроме `ai-help.md` и не из `log/`; подпись из `label` либо `id`).
- Кнопки Cancel / Run. Run неактивен при пустом промпте, при `loading`, если моделей нет.
- Если у выбранной модели пустой `api_key` — ошибка в том же warning-потоке, цикл не стартовать.
- Строки — через `locale` (EN+RU), ключи в `keys.rs` + `dict.json5`.
- Стили — существующие `.modal*` / `.games-full-btn`. Textarea вписать в текущий modal (чуть шире/выше допустимо, без нового «мастера»).

#### 6.1 `CreateGame` — кнопка в панели Local games

В `GamesPanel`, секция Local, **сразу под** кнопкой `Load Local Games` (`games-full-btn`):

- Текст вроде «Create new game with AI» (локализовать).
- Внешне как `games-full-btn`, `disabled` при `workspace.loading`.
- Клик → модальное окно «опишите желаемую игру».
- Submit → `AiRequest::CreateGame { prompt }` + выбранный `model_path`.

Кнопку New game на GitHub **не** трогать, если она где-то ещё есть.

#### 6.2 `EditGame` — `ai edit` в activity bar

В `ActivityBar` **сразу под** `SplitPreviewButton`:

- Кнопка в том же паттерне, что остальные activity (`ActivityButton` + tooltip + aria).
- Иконка: PNG off/on/click по образцу `addons/icons/buttons/<name>/`. **Бинарные PNG не генерировать.** Если ассетов нет в задаче — остановиться и спросить, не подменять SVG/`currentColor`.
- `disabled`, если `workspace.loading` **или** кнопка неактивна по правилу ниже.

Активна **только** если активный элемент рабочей области — **не автогенерируемый файл конкретной игры**:

- Берётся активный edit-tab (`active_tab` с `TabKind::Edit`); если его нет — выбранный в дереве **файл** (`selected`).
- Файл лежит внутри корня игры (каталог, в котором есть `game.json5`, см. `local_games` / `game_roots_from_paths`).
- Путь **не** является и **не** лежит под `_autogenerated`.
- Иначе (корень VFS, `user-help.md`, `ai-models/*`, `games/conf.json5` вне игры, папка, файл из `_autogenerated`) — неактивна.

Клик (если активна) → модалка «опишите изменения для этого файла».  
Submit → `AiRequest::EditGame { game, file, prompt }`, где `game` — корень игры, `file` — путь файла.

Предикат активности — чистая функция + unit-тест (игра / не игра / autogen / вне игры).

### 7. Прочее поведение

- Карты — это `views` + `decks/**/data.json5`, не картинки. Агент правит текст, HTML проверяет `prepare_html`.
- WASM: один `loading` на долгие операции; AI не параллелить с prepare/zip/load.
- Токены: в контекст не сбрасывать весь VFS. Модель сама делает `ls`/`read_file`.
- `arch.mermaid` — добавить узел `ai` (из workspace, HTTP через browser, VFS, `prepare_html`).
- Workspace Cargo: новый member + зависимость `workspace` → `ai` (ui **не** зависит от `ai` напрямую, если хватает методов workspace).

## Проверка корректности решения

Native-тесты (без WASM), плюс ручной смоук.

**Тесты**

- Парсинг json5 модели (gemini query-key, openai bearer, пустой ключ, optional rps).
- Песочница: `write_file`/`remove`/`mkdir` под `games/x/_autogenerated/...` — ошибка; `read_file` — можно; `prepare_html` пишет autogen.
- Предикат «ai edit активна»: файл в `games/a/decks/...` — да; `games/a/_autogenerated/...` — нет; `user-help.md` — нет; папка игры — нет.
- `install` help/ai-конфигов: нет файла → копия; пользовательский ключ в json5 → не затирать; HTML-shell → переустановить.
- Имя лог-файла: безопасные символы, папка `ai-models/log/`.

**Ручной смоук** (после сборки WASM)

1. Чистый старт: в корне VFS есть `game-help.md`, в `ai-models/` — четыре json5 + `ai-help.md`. Preview help открывается.
2. Без ключа: Create with AI → ошибка про `api_key`, VFS игр не испорчен.
3. Вписать ключ Gemini в json5 → Create with AI с коротким промптом → появляется `games/<id>/...`, лог в `ai-models/log/` открывается как Markdown, в логе видны tools и `prepare_html`.
4. Открыть исходник колоды (не autogen) → `ai edit` активна → промпт правки → файл изменился, autogen обновился через tool, не руками.
5. Вкладка `_autogenerated/.../preview.html` → `ai edit` неактивна.
6. DeepSeek/Grok без `proxy_url` → понятная ошибка CORS/blocked, не паника.

Сборку/тесты модуля гонять точечно (`cargo test -p deck_gen_wasm_ai`, плюс затронутые пакеты). Весь монорепо не гонять без нужды.

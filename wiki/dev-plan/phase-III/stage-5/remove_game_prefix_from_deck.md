# Задача: «conf.json5 → game.json5»

Необходимо убрать требование префикса в виде имени игры в параметре `name` для каждой колоды данной игры!

# Задача на доработку №1:
1. Необходимо убрать требование, чтобы имя колоды было равным имени папки в которой она находится → имя колоды может быть любым, но уникальным в рамках игры;
2. Необходимо убрать логику, которая проверяет не записан ли в имени колоды префиксом имя игры с целью поддержать обратную совместимость → имя игры и имя колоды не должны быть связаны никоем образом.

## Как проверить работоспособность
Игры для проверки находятся в папке `../Deck Games/` (см. `conf.json5`).
Должны работать команды генерации колод:
1. `deck_gen.exe pdf --game new-game`
1. `deck_gen.exe pdf --game "new-game"`
2. `deck_gen.exe pdf --game new-game --deck deck-1st`
2. `deck_gen.exe pdf --game "new-game" --deck deck-1st`
2. `deck_gen.exe pdf --game new-game --deck "колода №2"`
3. `deck_gen.exe pdf --game new-game --deck "дополнительная колода"`
4. `deck_gen.exe pdf --game "new-game" --deck "дополнительная колода"`

# Дополнительные указания
1. Целевой крейт для анализа `deck_gen` (другие файлы и крейты проекта ИГНОРИРУЙ)!
2. Изменения в коде должны быть минимальными.
3. Запрещено менять существующую архитектуру.
4. Крейты, код которых подвергался изменениям, должны проходить сборку и проверку локальными unit-тестами.
5. О результатах отпишись в `wiki\result.md` в формате `было→стало(почему)` (очисти файл, если там есть какое-то содержимое перед новой записью).
6. если от меня требуются какие-то действия, то пиши их в `wiki\note.md` (очисти файл, если там есть какое-то содержимое перед новой записью).

## Как правильно писать код:
1. этап-1: решить поставленную задачу и убедиться в её работоспособности;
   - первичный код необходимо писать простой, понятный и прямолинейный, без сложных абстракций;
   - если логика кода сложная, но позволяет написать простые unit-тесты для проверки, их надо написать;
2. этап-2: когда поставленная задача будет решена, код, созданный и зафиксированный на этапе-1, необходимо отрефакторить согласно правилам записанным в `wiki\prompts\refactoring-rules.md`
   - при организации кода придерживайся стиля той кодовой базы в которую вносишь изменения;
3. первый и второй этапы должны делаться раздельно, но в рамках одного промпта (решение → проверка → рефакторинг).

# Задача: «adjustable width»

В режиме split-preview (когда активна кнопка разделения), необходимо добавить возможность изменять относительные размеры левого (editor) и правого (preview) окон:
- уменьшить левое — правое вырастет на ту же величину;
- уменьшить правое — левое вырастет на ту же величину.

Визуально возможность активируется при наведении на стык между двумя половинами.
Появляется специальный ползунок-вкладочка; перетаскивание регулирует размеры.

Минимальный размер ширины каждого рабочего окна = 150px; значение задаётся в конфиге (deck_gen_wasm/conf/src/api.rs).

## Текущее состояние (из анализа кода)
- Когда `workspace.split_preview` == true, в `Editor` (ui/src/windows/editor/mod.rs) рендерится:
  ```html
  <div class="editor-split">
    <EditorPane preview_pane=false />
    <EditorPane preview_pane=true />
  </div>
  ```
- CSS: `.editor-split { grid-template-columns: 1fr 1fr; }` + border на втором.
- Нет ресайза, нет переменных ширины, нет handle.
- `EditorPane` рендерит tab header + body (flex column).

## Что сделать
1. Добавить в conf/src/api.rs (модуль `ui`):
   ```rust
   pub const SPLIT_PANE_MIN_WIDTH_PX: u32 = 150;
   ```
2. Сделать ширины панелей регулируемыми:
   - В `Editor` (или рядом) завести локальный сигнал(ы) текущих ширин (или одной left width в px или долях).
   - Применять к `.editor-split` через style: `--left-pane-width: ...px; --right-pane-width: ...px;` (или использовать grid с двумя minmax + var).
3. Вставить resizer-элемент между двумя `EditorPane` (внутри `.editor-split`).
4. Drag-логика (on:mousedown / window move / up):
   - Обновлять ширины с ограничением: каждая >= SPLIT_PANE_MIN_WIDTH_PX.
   - Сумма двух = доступная ширина контейнера (или использовать fr + фиксированный gutter).
5. Визуал:
   - На hover зоны стыка (или на самом resizer) показывать "ползунок-вкладочку".
   - cursor: col-resize.
   - Тонкая линия + grip.
6. Не требуется persist ширины split, синхронизация с main explorer width, анимации.

## Не делать
- Не трогать main .ide grid и app.rs (этим занимается задача change_width_of_fs_tree).
- Не менять Workspace / split.rs / state (ширины чисто presentation).
- Не трогать отдельные EditorPane internals, tab, preview и т.д. сверх вставки resizer'а.
- Не вводить общий Resizer-компонент в shared модуль (дублируй минимальную drag-логику если нужно, чтобы не менять архитектуру).
- Не затрагивать кнопки, explorer tree, контекстные меню.

## Приёмка
- В split-режиме потянув за стык можно перераспределять место между левой и правой половинами.
- Ни одна половина не может стать уже 150px.
- Grip/handle появляется только в split-режиме при наведении на стык.
- Обычный (не-split) режим и все остальные фичи без регрессий.
- Сборка + тесты (ui + conf + workspace) зелёные.
- Значения min берутся из conf.

# Дополнительные указания

## Как убедиться в правильности решения:
1. крейты, код которых подвергался изменениям, должны проходить сборку и проверку локальными unit-тестами;

## Как правильно писать код:
1. этап-1: решить поставленную задачу и убедиться в её работоспособности требуемым образом;
   - код необходимо писать простой, понятный и прямолинейный, без сложных абстракций;
   - если логика кода сложная, но позволяет написать простые unit-тесты для проверки, их надо написать;
2. этап-2: когда поставленная задача будет решена, код, созданный и зафиксированный на этапе-1, необходимо отрефакторить согласно правилам записанным в `wiki\prompts\refactoring-rules.md`
   - при организации кода придерживайся стиля той кодовой базы в которую вносишь изменения;

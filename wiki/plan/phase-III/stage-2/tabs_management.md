# Задача: «tabs management» (close all + rearrange)

Единая задача на улучшение работы с открытыми вкладками (editor tabs), т.к. close-all и reorder сильно пересекаются по изменяемым файлам и UI (полоса вкладок, EditorTab, tab lists в workspace).

## Подзадачи (реализовать вместе в рамках одного скоупа)
1. **Close all**: возможность закрыть все открытые вкладки. Доступно из ПКМ-меню любой вкладки.
2. **Rearrange**: возможность менять порядок вкладок перетаскиванием (как в VSCode).

## Текущее состояние (из анализа кода deck_gen_wasm)
- Управление: Workspace (state.rs, split.rs) — `tabs`, `preview_tabs`, `active_*`, `close_tab`, `open_tab`, partition/merge helpers.
- Рендер: Editor (mod.rs) → EditorPane (pane.rs) → For по табам → EditorTab (tab.rs).
- EditorTab имеет только close-кнопку ×. Нет contextmenu, нет drag.
- Explorer имеет полноценное ContextMenu; для табов ничего нет.
- Порядок = порядок в Vec; split разделяет два независимых списка.

## Что сделать (минимально)
### Общее
- Добавить необходимые методы на Workspace (в split.rs или state.rs):
  - `close_all_tabs(&self)`
  - `move_tab(&self, tab: OpenTab, to_index: usize)` (с учётом pane при split)
- Реализовать так, чтобы методы были чистыми по отношению к сигналам и покрыты unit-тестами.

### Close all
- По ПКМ на `EditorTab` (в любом pane) показать меню.
- Пункт "Close all" вызывает `close_all_tabs`.
- Можно использовать/минимально расширить существующий `ContextMenu`.
- Меню появляется в координатах клика, как для explorer.

### Rearrange (drag reorder)
- На EditorTab поддержать "нажал и перетащил".
  - Рекомендуется pointer-based (mousedown на tab → mousemove по документу → перестановка в реальном времени → mouseup).
  - Перестановка только внутри своей панели (left tabs ↔ left, preview ↔ preview).
- При перетаскивании давать визуальный feedback (изменение порядка live или индикатор вставки).
- Обновление порядка сразу отражается на `tabs`/`preview_tabs` сигналах.

## Не делать
- Не добавлять лишние пункты меню (Close others и т.п.).
- Не разрешать drag между левой и правой панелью при split.
- Не persist drag state.
- Не трогать main layout, explorer, activity buttons, ширины (кроме cursor:grab если в css).
- Не менять архитектуру workspace (не выносить TabList wrapper и т.д.).
- Не ломать существующие close single, activate, split toggle, open.

## Приёмка
- ПКМ на любой вкладке → меню с Close all → все вкладки (включая preview pane) закрываются.
- Drag любой вкладки внутри своей полосы меняет порядок; порядок сохраняется при активации/других действиях.
- Всё работает в split и non-split.
- Unit-тесты на reorder и close_all в workspace.
- Нет регрессий в существующих сценариях с табами.
- Сборка крейтов (workspace + ui) + тесты успешны.
- Код минимальный, прямолинейный.

# Задача: «deck-games catalog»

Необходимо доработать ui-представление левой панели в режиме Games (далее ЛП-Games).

## Особенности реализации:

### Как это устроено сейчас
Схематичное древовидное представление ui-элементов в иерархии их принадлежности с описанием ответственности:
```
«Games» (ui-кнопка левой боковой панели открывающая вкладку c играми)
    «Local» (ui-контейнер-секция ЛП-Games)
        «Load Local Games» (ui-кнопка активирующая модальное окно выбора папки для загрузки в локальную файловую систему (далее ЛФС))
    «Globals» (ui-контейнер-секция ЛП-Games)
        [ - произвольное количество элементов, зависящее от количества папок полученных с GitHub
            «Available Game» (ui-контейнер представляющий одну игру в контейнере Globals)
                «Name» (ui-текст содержащий имя игры = название папки с игрой)
                «settings» (ui-кнопка-выпадающий-список содержащая список команд, которые можно сделать с этой игрой (сейчас доступна единственная команда «Load Game»))
        ]
```

### Как это должно быть
Схематичное древовидное представление ui-элементов в иерархии их принадлежности с описанием ответственности:
```
«Games» (ui-кнопка левой боковой панели открывающая вкладку c играми)
    «Local» (ui-контейнер-секция на ЛП-Games)
        «Load Local Games» (ui-кнопка активирующая модальное окно выбора папки для загрузки в ЛФС)
        [ - произвольное количество элементов, зависящих от количества игр загруженных в ЛФС
            «Available Game» (ui-контейнер представляющий одну игру в контейнере Local)
                «Icon» (ui-виджет отображающий иконку игры)
                «Name» (ui-текст содержащий имя игры)
                «Settings» (ui-кнопка-выпадающий-список содержащая список команд, которые можно сделать с этой игрой (
                    доступные команды:
                    1. «Prepare HTML» - создаёт html для всех игровых колод данной игры
                    2. «Prepare PNG» - создаёт png для всех игровых колод данной игры
                    3. «Prepare PDF» - создаёт pdf для всех игровых колод данной игры))
        ]
    «Globals» (ui-контейнер-секция ЛП-Games)
        «Search» (ui-контейнер для поиска среди глобальных игр)
            «text-field» (ui-поле-ввода для ввода текста с целью поиска среди доступных игр)
            «search» (ui-кнопка при нажатии на которую активируется поиск среди доступных игр)
        [ - произвольное количество элементов, зависящее от количества игр обнаруженных в специальном GitHub репозитории - https://github.com/AlexeyPerestoronin/Deck-Games
            «Available Game» (ui-контейнер представляющий одну игру в контейнере Globals)
                «Icon» (ui-виджет отображающий иконку игры)
                «Name» (ui-текст содержащий имя игры)
                «Settings» (ui-кнопка-выпадающий-список содержащая список команд, которые можно сделать с этой игрой (доступна единственная команда «Load Game»))
        ]
```


### Как искать игры на Deck-Games
Все игры в данном репозитории находятся внутри папки Games.
Поиск игры - это обход в ширину содержимого данной папки с целью детектирования файла game.json5 наличие которого в папке, свидетельствует о том, что данная папка содержит какую-то игру.
Для того, чтобы понять какая именно игра была обнаружена необходимо скачать внутреннюю папку данной игры `<target-game-folder>/rules/preview`.
Данная папка содержит всю необходимую информацию о preview для игры.
Чтобы извлечь информацию необходимо прочить файл `info.json5`, который находится в этой папке (есл файла нет, то данная игра просто игнорируется) с следующим содержимым (пример для игры Покер):
```json5
{
    "preview": "preview.html",
    "icon": "info.png",
    "info": {
        "name": {
            "EN": "Poker",
            "RU": "Покер"
        },
        "tags": [
            "classic"
        ]
    }
}
```
Далее эта информация должен использоваться следующим образом:
1. html–файл, записанный в поле `preview` должен отображаться в режиме html-preview в новой вкладке рабочего пространства:
   - это главная афиша игры, которую видит пользователь;
   - если записи, или файла файла нет, то должно выводиться html-preview по умолчанию, на содержащая информацию, что для данной игры отсутствует preview
     - файл `default-preview.html` должен храниться в `deck_gen_wasm/template`
2. файл иконки, записанный в поле `icon`, должен отобразиться в ui-виджете «Icon» в «Available Games» для соответствующей игры:
   - если записи, или файла нет, то должна показываться иконка по умолчанию
     - файл `default-icon.png` должен храниться в `deck_gen_wasm/template`

# Дополнительные указания
1. Изменения в коде должны быть минимальными.
2. Запрещено менять существующую архитектуру крейта, до допускается менять архитектуру изменяемых модулей для удовлетворения целей задачи.
3. Крейты, код которых подвергался изменениям, должны проходить сборку и проверку локальными unit-тестами.
4. О результатах отпишись в `wiki\result.md` в формате `было→стало(почему)` (очисти файл, если там есть какое-то содержимое перед новой записью).
5. если от меня требуются какие-то действия, то пиши их в `wiki\note.md` (очисти файл, если там есть какое-то содержимое перед новой записью).

## Как правильно писать код:
1. этап-1: решить поставленную задачу и убедиться в её работоспособности;
   - первичный код необходимо писать простой, понятный и прямолинейный, без сложных абстракций;
   - если логика кода сложная, но позволяет написать простые unit-тесты для проверки, их надо написать;
2. этап-2: когда поставленная задача будет решена, код, созданный и зафиксированный на этапе-1, необходимо отрефакторить согласно правилам записанным в `wiki\prompts\refactoring-rules.md`
   - при организации кода придерживайся стиля той кодовой базы в которую вносишь изменения;
3. первый и второй этапы должны делаться раздельно, но в рамках одного промпта (решение → проверка → рефакторинг).
4. рефакторинг также должен проверить новую кодовую базу на наличие мёртвого кода и ненужных тестов (это нужно удалить).

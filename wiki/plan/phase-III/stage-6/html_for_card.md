# Задача: «one card one html/pdf»

Необходимо сделать так, чтобы для каждой карты в колоде создавалось отдельное уникальное для карты html-представление, а не только общие файлы `back.html` и `face.html`, которые создаются сейчас.

Важные моменты:
1. уникальные html-представления для каждой карты должны собираться в рамках специальной папки `<new-game>/_autogenerated/<deck-name>/cards/html/card-N-(face|back).html`
    пример для колоды `deck-1st` в игре `new-game`, состоящей из 4 карт:
    ```
    new-game/
        _autogenerated/
            deck-1st/
                cards/
                    html/
                        card-1-back.html
                        card-1-face.html
                        card-2-back.html
                        card-2-face.html
                        card-3-back.html
                        card-3-face.html
                        card-4-back.html
                        card-4-face.html
                back.html
                back.pdf
                face.html
                face.pdf
                preview.html
                a4-duplex.pdf
    ```
2. файлы face.html и back.html должны составляться из списка соответствующих карт в `cards`, чтобы при изменении конкретной карты это автоматически сказывалось и на `(front|back).html`.

# Что необходимо сделать
<Добавить генерацию уникальных HTML-представлений для каждой карты (card-N-face.html и card-N-back.html) в поддиректорию cards/html/ внутри _autogenerated/<deck-name>/ (рядом с face.html, back.html и т.д.).

Каждый per-card HTML — это полноценный standalone-документ, полученный рендерингом face/back-шаблона с контекстом, где `cards` содержит ровно одну карту (slice из 1 элемента). Номер N — 1-based по порядку в колоде.

Существующие face.html и back.html (листы со всеми картами) продолжают генерироваться в точности как сейчас (рендер полного списка `cards`). Их содержимое и пути записи не меняются. Это гарантирует автоматическое обновление листов при правке отдельной карты (т.к. все ре-генерируются из общих данных).

По анализу кода: логика создания PDF меняться НЕ должна и связанный код (pdf_engine/* , prepare_pdf_named) меняться НЕ должен. В pdf_engine/mod.rs prepare_pdf_named вызывает render::prepare_html (получает пути к sheets), читает face/back.html и передаёт в engine. Всё продолжит работать без правок в pdf_engine, host, cli (для pdf). Изменения локализованы в render.rs.>

1. Изменения в коде должны быть минимальными.
2. Запрещено менять существующую архитектуру.
3. Крейты, код которых подвергался изменениям, должны проходить сборку и проверку локальными unit-тестами.
4. О результатах отпишись в `wiki\result.md` в формате `было→стало(почему)` (очисти файл, если там есть какое-то содержимое перед новой записью).
5. если от меня требуются какие-то действия, то пиши их в `wiki\note.md` (очисти файл, если там есть какое-то содержимое перед новой записью).

## Как правильно писать код:
1. этап-1: решить поставленную задачу и убедиться в её работоспособности;
   - первичный код необходимо писать простой, понятный и прямолинейный, без сложных абстракций;
   - если логика кода сложная, но позволяет написать простые unit-тесты для проверки, их надо написать;
2. этап-2: когда поставленная задача будет решена, код, созданный и зафиксированный на этапе-1, необходимо отрефакторить согласно правилам записанным в `wiki\prompts\refactoring-rules.md`
   - при организации кода придерживайся стиля той кодовой базы в которую вносишь изменения;
3. первый и второй этапы должны делаться раздельно, но в рамках одного промпта (решение → проверка → рефакторинг).

## Как правильно проверять работоспособность:
Соседней папке рядом с папкой проекта находится папка Deck Games (`C:/MyLife/Deck Games`), где находятся игры на которых можно проверять работоспособность.
Работоспособность проверяется на игре new-game (`C:/MyLife/Deck Games/Templates/new-game`).
Должны выполняться следующие команды:
1. `deck_gen.exe list`
2. `deck_gen.exe html --game new-game`

4. `deck_gen.exe pdf --game "new-game"`
5. `deck_gen.exe pdf --game new-game --deck deck-1st`
6. `deck_gen.exe pdf --game "new-game" --deck deck-1st`
7. `deck_gen.exe pdf --game new-game --deck "колода №2"`
8. `deck_gen.exe pdf --game new-game --deck "дополнительная колода"`
9. `deck_gen.exe pdf --game "new-game" --deck "дополнительная колода"`

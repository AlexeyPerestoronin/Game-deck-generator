# Задача
Добавить уникальные иконки слева от имени файла в дереве Explorer для расширений `*.js` и `*.j2`.

## Текущее поведение (факт из кода)
- Классификация иконок — `deck_gen_wasm_fs::kind::explorer_icon` (`deck_gen_wasm/fs/src/file_kind.rs`).
- Для `js` и `j2` функция возвращает `None`.
- UI рисует иконку в `FileTypeIcon` (`deck_gen_wasm/ui/src/icons/files.rs`): `None` → пустой слот `<span class="file-icon-slot">`, чтобы колонка не съезжала.
- Иконки остальных типов — инлайн SVG 16×16 (`viewBox="0 0 16 16"`, класс `file-icon`).
- `FileKind` / `syntax_name` / импорт `js`/`j2` уже работают; эту задачу они не касаются. Варианты `Js`/`J2` в `FileKind` добавлять не нужно.

## Что сделать
1. В `ExplorerIcon` добавить два варианта: `Js` и `J2`.
2. В `explorer_icon` маппить расширение `js` → `ExplorerIcon::Js`, `j2` → `ExplorerIcon::J2` (как у `md`/`html`: только эти расширения, без алиасов).
3. В `FileTypeIcon` добавить две отдельные SVG-иконки в том же стиле, что существующие (документ 16×16 + различимый знак типа).
   - Иконки `js` и `j2` должны отличаться друг от друга и от JSON/HTML/SCSS.
   - Размер слота не менять: 16×16, класс `file-icon`.
4. Неизвестные типы по-прежнему получают пустой слот.

## Не делать
- Не менять `FileKind`, `kind_of`, `syntax_name`, `can_highlight`, импорт, preview.
- Не выносить иконки в PNG/файлы (это другая задача — `flixible_icons.md`, и она про кнопки Activity Bar).
- Не трогать папки, `new_file`/`new_folder`, контекстное меню.

## Приёмка
- В дереве у `script.js` и `face-layout.j2` слева от имени видны разные иконки, не пустой слот.
- `help.md`, `data.json5`, `page.html`, `style.scss`, `face.pdf`, `logo.png` без регрессий.
- `notes.txt` / файлы без расширения — по-прежнему пустой слот.
- Unit-тесты: `explorer_icon("a.js") == Some(Js)`, `explorer_icon("a.j2") == Some(J2)`; регистр расширения как у остальных (`JS` тоже Js).

***

`js`/`j2` уже есть в `conf::ext::IMPORT_TEXT` и подсвечиваются через `syntax_name`. Иконка Explorer — отдельная таблица `explorer_icon` + `FileTypeIcon`; conf трогать не нужно.

1. крейты, код которых подвергался изменениям, должны проходить сборку и проверку локальными unit-тестами;

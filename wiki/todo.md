# Задача
Необходимо добавить возможность разделения для рабочей области на две части (правую и левую), где левая часть будет ответственна за редактирование выбранного компонента, а правая часть за его preview.

Важные моменты:
- возможность разделения рабочей области на две части должна активироваться нажатием кнопки `split for preview`, которую необходимо добавить на левую панель (ActivityBar):
  - однократное нажатие по кнопке приводит к тому, что рабочая область разделяется на две половины, а кнопка изменяет свою визуальную компоненту для демонстрации активации (становится синей);
  - повторное нажатие по кнопке приводит к тому, что рабочая область становится обычной, а кнопка изменяет свою визуальную компоненту на обычную для демонстрации дезактивации (становится обычной);
- при активации `split for preview` происходит следующая логика:
  - все preview-вкладки для всех файлов перемещаются на правую часть (обычные файлы остаются открытыми на левой части);
    - если открытых preview не было, то правая часть остаётся без вкладок (пустой)
  - при открытии файла, для которого возможна демонстрация preview и вкладки с таковым ещё нет, соответствующая вкладка открывается автоматически на правой стороне (а сам файл на левой, как это и есть сейчас);
- при дезактивации `split for preview` все вкладки, которые были открыты на левой стороне перемещаются в общий пул вкладок неделимой рабочей области (как это и есть сейчас);

# Особые указания
1. Какой код использовать для анализа:
   - крейт `deck_game_wasm`
   - прочие файлы и папки репозитория ИГНОРИРУЙ;
2. Как убедиться в правильности решения:
   - крейты, код которых подвергался изменениям, должны проходить сборку и проверку локальными unit-тестами;
3. Как правильно писать код:
   - этап-1: необходимо решить поставленную задачу и убедиться в её работоспособности требуемым образом;
       - код необходимо писать простой, понятный и прямолинейный, без сложных абстракций;
       - если логика кода сложная, но позволяет написать простые unit-тесты для проверки, их надо написать;
   - этап-2: когда поставленная задача будет решена, код, созданный и зафиксированный на этапе-1, необходимо отрефакторить согласно правилам записанным в `wiki\prompts\refactoring-rules.md`
       - при организации кода придерживайся стиля той кодовой базы в которую вносишь изменения;
4. Краткий отчёт (50-100 строк) о проделанной работе в формате `было→стало(почему)` напиши в `wiki\result.md`.
5. Если какие-то пост-действия требуются от меня напиши их в `wiki\note.md`.

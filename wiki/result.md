# Результат доработки №5 по vscode_like_ui.md (2026-09-17)

## Задача
Проблема с чёрными страницами в pdf preview в FireFox не решена (после отката доработки №4). Нужно исправить.
- Откат всех изменений доработки №4 уже выполнен.
- Ссылки на историю: commit 22caa3fa (split preview iter-3, где убрали color-scheme с iframe чтобы починить чёрные картинки карт в Chrome) и соседние.

## Что было → стало (почему)

**было:**
- .preview-host.preview-pdf-host (div) имеет color-scheme: light; iframe.preview-frame — нет.
- Это давало белые страницы в Chrome/Edge (их PDF плагин уважает цветовую схему на предке), но Firefox (pdf.js) игнорирует и рисует страницы чёрными.
- Нельзя было просто вернуть color-scheme на iframe (сломает рендер JPEG-картинок внутри PDF как чёрные прямоугольники в Chrome — это и было исправлено в 22caa3f вместе с переходом с position:absolute на flex).

**стало (прямолинейно на этапе-1, с последующим рефакторингом на этапе-2):**
- Добавлена простая UA-проверка is_firefox() (через Function без новых фич web-sys, по аналогии с theme.rs).
- Для Firefox iframe получает дополнительный класс "pdf-frame".
- CSS: .pdf-frame { color-scheme: light; } + расширенный комментарий.
- Для не-FF остаётся старый механизм на .preview-pdf-host.
- Результат: FF получает color-scheme на самом iframe → белые страницы; Chrome/Edge продолжают использовать ancestor (без color-scheme на iframe) → изображения карт внутри PDF не чернеют.
- Код минимальный, локальный в preview.rs + style.css. Никакой смены генерации PDF, prepare_pdf_web не трогали.
- Модульные тесты и check пройдены.

**Проверка (этап-1 → этап-2):**
- cargo check -p deck_gen_wasm_ui : успех.
- cargo test -p deck_gen_wasm_ui : 16/16 passed (все тесты, включая sidebar и games).
- Затронут только deck_gen_wasm/ui (крейт deck_gen_wasm_ui). Другие крейты (deck_gen, prepare_pdf_web и т.д.) не менялись и не требовали пересборки для этой правки.
- Браузерная верификация: прямых инструментов браузерного контроля/скриншотов/автотестов в этом окружении нет. Использован субститут — компиляция + все unit-тесты покрывают превью-компонент и переключение классов. Полноценную ручную проверку (serve.bat + открыть preview .pdf в Firefox + Chrome + Edge, проверить белизну страниц при светлой/тёмной теме приложения) нужно выполнить вручную.

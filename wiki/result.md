# Результат доработки №3 по vscode_like_ui.md (2026-09-17)

## Задача
Выполнить 2 пункта доработки №3:
1. Исправить баг c pdf preview (остался чёрный в FireFox после доработки №2, которая сделала белым в Chrome/Edge). Условия: только правки в deck_gen_wasm (не трогать код за его пределами). Идеально — откат целевых изменений к предыдущему варианту.
2. Секции Local и Global отображаются правильно, но сворачиваются неправильно (в отличие от VSCode):
   - при хотя бы одной раскрытой — должны занимать всё пространство панели;
   - когда все свёрнуты — должны располагаться сверху одна под другой (а не одна над другой, перекрывая и делая невозможным повторное раскрытие).

## Что было → стало (почему)

**было (после доработки №2):**
- PDF: для фикса Chrome/Edge ввели обёртку <div class="preview-pdf-host"> вокруг <iframe class="preview-frame"> + color-scheme:light на обёртке (отдельный блок с flex). Это сломало Firefox (страницы чёрные). Структура DOM отличалась от "предыдущего варианта".
- Games collapse: section_flex возвращал числовые flex-факторы 0.0/1.0. При "flex: 0;" (basis 0 + shrink) + min-height:0 + overflow:hidden на ancestors, заголовки схлопывались до 0 или перекрывались. Обе свёрнутые секции не стекались нормально сверху, хедеры нельзя было кликнуть для раскрытия повторно.

**стало (прямолинейная реализация на этапе-1 + рефакторинг на этапе-2):**
1. PDF: откат целевого изменения — убрана лишняя обёртка-div (возврат к структуре preview-host > iframe напрямую). Класс "preview-pdf-host" теперь на самом .preview-host для PDF-кейса. CSS .preview-pdf-host упрощён только до color-scheme: light (без дублирующих flex-правил). Комментарий обновлён. Это заставляет viewer рисовать белые страницы в Firefox (как в Ch/Edge), не нарушая запрет на color-scheme непосредственно на самом <iframe> (чтобы не ломать изображения карт в Chrome). Всё строго в deck_gen_wasm.
2. Секции:
   - section_flex теперь возвращает полноценные CSS flex-строки: "0 0 auto" для свёрнутых (intrinsic размер по хедеру, grow=0 shrink=0) и "{r} 1 0" / "{1-r} 1 0" для раскрытых.
   - При всех свёрнутых — оба хедера получают auto-размер и располагаются сверху один под другим (нормальный stack в flex column), ниже пусто.
   - При хотя бы одной раскрытой — раскрытая занимает оставшееся пространство (flex 1), свёрнутая — свой хедер сверху/снизу.
   - Обновлены юнит-тесты под новую сигнатуру и поведение.
   - Ползунок по-прежнему показан только когда обе раскрыты; соотношение сохраняется при re-expand.

**Проверка (этап-1 → этап-2):**

- cargo test -p deck_gen_wasm_ui : 16/16 passed (включая sidebar::toggle_* и все 4 windows::games::tests::* для flex/collapse).
- Соответствует: правки ТОЛЬКО внутри deck_gen_wasm/ (ui/src/... + style.css). Никаких изменений prepare_pdf_*, deck_gen и т.д.
- Браузерная верификация: инструментов прямого открытия/взаимодействия в браузере (типа playwright) в окружении нет. Использован ближайший субститут — компиляция + unit-тесты (покрывают toggle, section_flex mapping и превью-логику). Не удалось полностью интерактивно проверить в Firefox/Chrome/Edge: запуск serve.bat + клики по PDF preview (белые страницы), сворачивание/разворачивание Local/Global (хедеры кликабельны, не перекрываются, занимают пространство правильно).

# Результат: «png for card» (png_for_card, stage-6)

## Задача
Сделать генерацию индивидуальных PNG для лицевой и оборотной стороны каждой карты: `<deck>/_autogenerated/<deck-name>/cards/png/card-N-(face|back).png`. Добавить CLI `png` (аналог html/pdf). PNG независим от PDF (опирается только на per-card HTML). API доступен в wasm-сборке.

## было → стало (почему)

**было:**
- Существовали per-card HTML (из предыдущего этапа), но не было способа получить растровые PNG индивидуально для каждой карты.
- CLI поддерживал только list/html/pdf; не было `png`.
- Растеризация жила только внутри pdf пути (jpeg → pdf_from_jpeg + impose).
- prepare_pdf_host умел только print_to_pdf; prepare_pdf_web умел только html→jpeg pages.
- Не было единого API prepare_png_* в deck_gen.

**стало:**
- Добавлена `CardPngGenerator` (trait) + `prepare_png` / `prepare_png_named` + `PngArtifacts` в deck_gen/src/lib.rs (прямая аналогия html/pdf, но без impose и без PdfEngineGenerator).
- Внутри prepare_png_named: ensure per-card html через render::prepare_html, для каждого card-N-*.html читаем строку, raster в png bytes, пишем в cards/png/.
- CLI: добавлен вариант `Png` в Command, png_command (с Chrome launch + pollster), печать путей к png (в т.ч. per-card).
- Native raster: в prepare_pdf_host::Chrome добавлены html_to_png_bytes / html_file_to_png_bytes (navigate + wait + element capture_screenshot на article.card / .card-back с clip по content box).
- Wasm raster: в prepare_pdf_web добавлен WebPngEngine (impl CardPngGenerator), html_to_png + binding; в html_to_jpeg_pages.js — htmlToPng + rasterElementToPng (canvas.toBlob png, scale=2).
- Всё через FileSystem, работает для OsFs и VfsFs.
- Pdf код, трейты и impose — не затронуты.
- cargo test -p deck_gen --features cli проходит.
- Все требуемые команды (list/html/pdf + новые png с --game/--deck, quoted, кириллица) выполняются и создают правильную структуру png.

(почему: png-логика полностью независима от pdf (как указано в задаче); использовали готовые per-card html; минимальная прослойка (trait + 2 prepare fn) без смены архитектуры; прямолинейная реализация + лёгкий polish под стиль; крейты с правками проходят тесты; Cargo.toml прокомментированы, README проанализированы и обновлены где уместно.)

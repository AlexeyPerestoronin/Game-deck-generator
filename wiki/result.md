# PDF preview в `deck_gen_wasm`

Краткий отчёт в формате было→стало(почему). Менялся только крейт `deck_gen_wasm`.

## Контекст-меню проводника

- **Было:** `is_previewable` допускал только `html` / `htm` / `md` / `markdown`.
- **Стало:** в список добавлен `pdf`.
- **Почему:** пункт Preview должен появляться у PDF так же, как у HTML и Markdown.

- **Было:** комментарий к `commands_for` говорил только про html/md.
- **Стало:** комментарий упоминает html/md/pdf.
- **Почему:** документация не должна расходиться с реальным списком команд.

- **Было:** тестов на состав меню не было.
- **Стало:** `preview_menu_for_html_md_pdf` проверяет Preview у html/md/pdf и его отсутствие у json5 и папок.
- **Почему:** список расширений легко сломать при следующем изменении меню.

## Вкладка Preview vs бинарная заглушка

- **Было:** в `Editor` сначала проверялся `vfs.is_binary(path)`, потом `TabKind::Preview`.
- **Стало:** сначала Preview, потом заглушка «Binary file (N bytes)».
- **Почему:** PDF в VFS — `Node::Binary`; старый порядок глушил preview даже после команды Preview.

- **Было:** клик по PDF по-прежнему открывает Edit и показывает размер.
- **Стало:** это поведение не трогали.
- **Почему:** у HTML/MD клик тоже открывает исходник; Preview — отдельная команда меню.

## Рендер preview

- **Было:** `PreviewPane` выбирал HTML iframe или Markdown HTML; любой другой тип шёл в Markdown.
- **Стало:** ветка `"pdf"` рисует `PdfPreview` в том же `preview-frame`.
- **Почему:** PDF нельзя показать через `srcdoc` или `inner_html`.

- **Было:** для HTML iframe брал текст из `read_file` и подставлял `srcdoc`.
- **Стало:** для PDF берётся `read_bytes`, из него Blob `application/pdf` и object URL в `iframe.src`.
- **Почему:** PDF — байты, не UTF-8; встроенный viewer браузера открывает blob URL.

- **Было:** URL не создавались и не освобождались.
- **Стало:** `pdf_blob_url` / `replace_object_url` / `revoke_object_url`; `on_cleanup` снимает URL при закрытии вкладки.
- **Почему:** каждый `createObjectURL` держит копию файла в памяти браузера.

- **Было:** любой сигнал VFS мог бы пересоздавать blob (если читать VFS прямо в Effect).
- **Стало:** `Memo` по байтам конкретного пути; blob пересобирается только если PDF изменился.
- **Почему:** правки json5/html не должны крутить PDF-viewer и копить URL.

## Комментарии и типы

- **Было:** `TabKind::Preview` описан как «HTML / Markdown».
- **Стало:** «HTML / Markdown / PDF».
- **Почему:** enum тот же, смысл вкладки шире.

- **Было:** шапка `editor/mod.rs` не знала про PDF.
- **Стало:** описаны три режима preview.
- **Почему:** модульный комментарий должен отражать фактические ветки.

- **Было:** у `PreviewPane` не было rustdoc.
- **Стало:** короткий комментарий, что тип preview выбирается по расширению.
- **Почему:** правило рефакторинга — документировать публичные элементы модуля.

## Зависимости и CSS

- **Было:** `web-sys` уже с `Blob`, `BlobPropertyBag`, `Url`; `js-sys` уже с typed arrays.
- **Стало:** новых крейтов нет; те же API, что ZIP-download.
- **Почему:** YAGNI — не тащить pdf.js, пока хватает iframe + blob.

- **Было:** `.preview-frame` на весь editor pane.
- **Стало:** PDF iframe использует тот же класс.
- **Почему:** визуально preview PDF совпадает с HTML preview.

## Что не меняли

- **Было:** VFS хранит PDF как `Binary`, не кладёт их в localStorage.
- **Стало:** без изменений.
- **Почему:** preview читает уже существующий `read_bytes`; персист трогать не нужно.

- **Было:** `prepare_pdf` пишет байты в дерево.
- **Стало:** без изменений.
- **Почему:** задача — показ файла, не генерация.

- **Было:** прочие крейты репозитория.
- **Стало:** не анализировались и не правились.
- **Почему:** так сказано в `todo.md`.

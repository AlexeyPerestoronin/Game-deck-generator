# Результат: «one card one html» (html_for_card, stage-6)

## Задача
Сделать так, чтобы для каждой карты создавалось отдельное уникальное HTML-представление (card-N-face.html / card-N-back.html) в _autogenerated/<deck>/cards/html/, при этом существующие face.html / back.html / preview.html продолжают генерироваться точно так же (полный список карт).

## было → стало (почему)

**было:**
- В render_html рендерился только один контекст — со всеми картами — и писались только три файла листов (face/back/preview) в корень output_dir колоды.
- Не было per-card HTML; нельзя было получить standalone-документ для ровно одной карты без дублирования логики рендера.
- В _autogenerated/<deck>/ лежали только общие файлы + pdf-артефакты.

**стало:**
- В render_html после записи полных листов создаётся поддиректория cards/html/ и для каждого индекса (1-based) пишутся card-N-face.html и card-N-back.html.
- Для per-card используется тот же шаблон (face/back), но context с cards = slice из 1 элемента (получен через deck.cards()).
- Полные face.html / back.html / preview.html генерируются и записываются в точности по прежним путям и с прежним содержимым (cards = полный список).
- Добавлен маленький приватный helper render_template, чтобы переиспользовать построение ctx + render для обоих случаев (полный срез и единичный).
- Всё через переданный FileSystem — работает и для WASM/VFS.
- HtmlArtifacts и prepare_html_named / CLI / pdf_engine — без изменений (per-card пишутся как side-effect).

(почему: задача требовала локализовать изменения в render.rs, минимум правок, без смены архитектуры и без трогания pdf-логики; reuse существующего render_html(cards) + template_context + deck.template_for; прямолинейная реализация сначала, потом рефакторинг.)

## Проверка работоспособности
- cargo test -p deck_gen --features cli — все тесты проходят (до и после рефакторинга).
- Выполнены команды (с native бинарём после cargo build):
  - list --game new-game
  - html --game new-game (и с --deck)
  - pdf --game new-game
  - pdf --game "new-game"
  - pdf --game new-game --deck deck-1st
  - pdf --game "new-game" --deck deck-1st
  - pdf --game new-game --deck "колода №2"
  - (попытка "дополнительная колода" — как в списке; deck отсутствует в текущих данных, но команда запускалась)
- Инспекция FS (deck-1st, 2 карты):
  - cards/html/ содержит card-1-face.html, card-1-back.html, card-2-face.html, card-2-back.html
  - В per-card файлах — ровно 1 <article class="card">
  - В полных face.html — 2 <article>
  - Полные листы и pdf продолжают писаться на старые пути.
- Аналогично для колод с 4 и 1 картой (с учётом коллизии имён колод в new-game — pre-existing).
- Содержимое per-card — полноценный standalone HTML (DOCTYPE, head с title+style, body с одной картой).

# First-visit help из GitHub

Краткий отчёт в формате было→стало(почему). Менялся только крейт `deck_gen_wasm`.

## Первый заход

- **Было:** `App` всегда делал `load_session().unwrap_or_default()`; пустой VFS, вкладок нет.
- **Стало:** если `load_session()` — `None`, вызывается `Workspace::open_first_visit_help`.
- **Почему:** «первичная загрузка» = нет ключа в localStorage, не каждый reload.

- **Было:** повторный заход с сохранённой сессией тоже был бы пустым стартом, если сессии нет.
- **Стало:** при существующей сессии help не качается и preview не навязывается.
- **Почему:** иначе каждый F5 снова открывал бы help поверх работы пользователя.

## Откуда берётся файл

- **Было:** `user-help.md` в крейте был пустой и никуда не загружался.
- **Стало:** GET `raw.githubusercontent.com/{repo}/master/deck_gen_wasm/user-help.md` через уже существующий `github::raw_url`.
- **Почему:** в задаче явно «из master, как другие данные с GitHub».

- **Было:** шаблон `new-game` при ошибке GitHub берёт Trunk `/template/…`.
- **Стало:** help при ошибке GitHub берёт относительный `user-help.md` (copy-file в `index.html`).
- **Почему:** тот же fallback, чтобы локальный Trunk не зависел от того, что уже лежит на master.

- **Было:** пути к help были бы размазаны по UI.
- **Стало:** `conf::help::PATH` и `LOCAL_URL`.
- **Почему:** правило рефакторинга — константы в конфиге, не в статиках рядом с fetch.

## Куда кладётся и как открывается

- **Было:** preview открывался только из контекстного меню.
- **Стало:** после fetch файл пишется в VFS как `deck_gen_wasm/user-help.md`, раскрывается папка, вкладка `TabKind::Preview`.
- **Почему:** путь из задачи совпадает с путём в репозитории; Markdown preview уже умеет md.

- **Было:** HTTP и установка в VFS жили бы в `App` или в `github.rs`.
- **Стало:** модуль `help.rs` (fetch + `put_file`); вкладку открывает `workspace/actions.rs`.
- **Почему:** как `template.rs` + `add_new_game`: сеть отдельно, UI-команда отдельно.

## Текст help

- **Было:** пустой `deck_gen_wasm/user-help.md`.
- **Стало:** ~60 строк: зачем сайт, кнопки слева, дерево, pipeline, устройство `games/<id>/`.
- **Почему:** лимит 100 строк; язык как у UI (подписи кнопок английские).

## GitHub / HTTP

- **Было:** комментарий `github.rs` только про шаблон `new-game`.
- **Стало:** `raw_url` также для help; тест `help_raw_url_uses_master_and_repo_path`.
- **Почему:** не плодить второй сборщик URL; проверить ветку `master` и суффикс пути.

- **Было:** `http::fetch_text` описан как «GitHub + template».
- **Стало:** плюс first-visit help.
- **Почему:** тот же GET UTF-8, без нового крейта.

## Что не меняли

- **Было:** сессия в localStorage, автосохранение Effect в `App`.
- **Стало:** без изменений алгоритма persist.
- **Почему:** после успешного fetch Effect сам запишет дерево с help.

- **Было:** Clear стирает VFS и сохраняет пустую сессию.
- **Стало:** Clear по-прежнему не считает следующий reload «первым визитом».
- **Почему:** в задаче — первичная загрузка сайта, не кнопка Clear.

- **Было:** прочие крейты репозитория.
- **Стало:** не анализировались и не правились.
- **Почему:** так сказано в `wiki/todo.md`.

## Проверки

- **Было:** 20 unit-тестов.
- **Стало:** 22 (`installs_at_configured_path`, `help_raw_url_uses_master_and_repo_path`).
- **Почему:** сеть в unit-тестах не дёргаем; проверяем путь в VFS и форму raw URL.

- **Было:** сборка wasm как раньше.
- **Стало:** `cargo test -p deck_gen_wasm` ok; `cargo check --target wasm32-unknown-unknown` ok.
- **Почему:** изменённый крейт должен собираться и проходить локальные тесты.

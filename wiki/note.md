# Рефакторинг №-1: «`Vfs::get()` клонирует всё дерево на каждый реактивный кадр»

Описание проблемы:
`Vfs` — глубоко `Clone` (`BTreeMap` + строки + тела файлов, включая `Vec<u8>` бинарников). `RwSignal<Vfs>::get()` в Leptos копирует **весь** воркспейс. Так читают дерево редактор (`highlighted.rs`, `plain.rs`, `preview.rs`, `pane.rs`), эксплорер (`tree.rs` → `flatten_tree`), статусные действия и автосейв (`app.rs`: `workspace.vfs.get().binary_entries()`). На каждый символ в textarea это полный clone дерева + (для подсветки) ещё один clone в соседнем замыкании.

Предлагаемое решение:
В горячих путях заменить `vfs.get()` на `vfs.with(|vfs| …)` / `vfs.read()` (без clone). Clone оставить только там, где владение нужно (`prepare_*` отдаёт дерево в `VfsFs`, ZIP, снимок сессии). Не менять модель `Node`/`Vfs`.

Ожидаемый эффект:
Резкое снижение аллокаций при наборе текста, смене вкладки и перерисовке дерева; меньше пауз в WASM (один поток).

Ваше решение: подтверждают!

# Рефакторинг №-2: «Автосейв в `LoadedApp` пишет localStorage и трогает бинарники на каждое изменение VFS»

Описание проблемы:
`Effect` в `app.rs` на любой реактивный вход `snapshot()` (`vfs` / `selected` / `expanded`) делает `serde_json` + `localStorage.setItem` и `binary_entries()` (обход + clone всех PDF/картинок) ради fingerprint. Набор текста в файле = полный JSON-снимок на каждый input. Квота и main thread страдают; `persist()` с activity bar дублирует ту же запись.

Предлагаемое решение:
Не менять формат сессии. Отделить «грязный» текстовый снимок от бинарного: debounce (например 200–400 ms) или запись только по `untrack` + явному флагу «vfs изменился». Fingerprint считать без промежуточного `Vec<(String, Vec<u8>)>` (обход дерева на месте) либо сравнивать поколение/счётчик мутаций VFS. Ручной Save оставить как сейчас.

Ожидаемый эффект:
Набор текста не блокируется сериализацией; IndexedDB не сканируется, пока бинарники не менялись.

Ваше решение: подтверждают! → Ручной Save оставить как сейчас + debounce в 300 ms

# Рефакторинг №-3: «Подсветка syntect на каждый символ без кэша и debounce»

Описание проблемы:
`HighlightedEditor` на каждый `vfs` input вызывает `highlight_html`: полный проход TextMate по всему файлу (`LinesWithEndings` + `ClassedHTMLGenerator`). `SyntaxSet` уже в `OnceLock` — это хорошо; повторный parse всего буфера — нет. Плюс `html_escape` fallback копирует весь текст три раза (`replace` цепочкой).

Предлагаемое решение:
Debounce пересчёта HTML (как у тултипов, через `gloo-timers`) или мемоизация по `(path, длина, простой fingerprint содержимого)`. Escape оставить одним проходом. Грамматики и список расширений не менять.

Ожидаемый эффект:
Редактор больших `html`/`json5` перестаёт подлагивать при печати.

Ваше решение: подтверждают! → Debounce пересчёта HTML как у тултипов, через `gloo-timers`

# Рефакторинг №-4: «Сбор бинарников и ZIP копирует все байты во временные векторы»

Описание проблемы:
`binary_entries` / `collect_binaries` и `files_and_dirs` / `collect_entries` кладут в `Vec<(String, Vec<u8>)>` clone каждого файла. Автосейв, restore и ZIP (`vfs_to_zip`) всегда платят полную копию. Для ZIP текстовые файлы ещё раз копируются из `String` в `Vec<u8>` (`content.as_bytes().to_vec()`), хотя `write_all` принимает `&[u8]`.

Предлагаемое решение:
ZIP: писать из `&Vfs` напрямую (обход дерева → `start_file` + `write_all` по `&str`/`&[u8]`), без промежуточного списка копий. Для IndexedDB — кодировать в JS-объект из обхода, не собирая Rust-`Vec` копий (или принимать `impl Iterator`). Сигнатуры UI можно сузить позже, не трогая формат IDB.

Ожидаемый эффект:
Меньше пик-памяти при Download и при каждом автосейве бинарников; быстрее ZIP на больших PDF.

Ваше решение: подтверждают!

# Рефакторинг №-5: «GitHub-блобы шаблона качаются строго по одному»

Описание проблемы:
`github::fetch_listed_blobs` в цикле `await` на каждый raw-URL. WASM однопоточен по CPU, но сеть может идти параллельно. Сейчас «New game» = N последовательных RTT. Ошибки отдельных файлов глотаются — это текущая политика, её не менять.

Предлагаемое решение:
Тот же skip-on-error, но `join`/`future::try_join` ограниченным пулом (например 6–8 одновременных `fetch_text`). Без web workers и без изменения URL/фильтра путей.

Ожидаемый эффект:
Установка `new-game` заметно быстрее на обычном канале.

Ваше решение: подтверждают!

# Рефакторинг №-6: «Обход папки с диска читает файлы строго последовательно»

Описание проблемы:
`collect_tree` / `collect_from_file_list` / `take_file`: на каждый файл `await` `getFile` + `text()`/`array_buffer()`. Это I/O браузера; последовательность не нужна для корректности. Классификация расширений и reject-всего-батча остаются как есть.

Предлагаемое решение:
Сначала синхронно классифицировать (size + имя), затем параллельно (ограниченный join) читать только допущенные файлы. Reject/oversized по-прежнему собираются до install.

Ожидаемый эффект:
«Load Game» / «load file(s)» быстрее на папках с десятками файлов.

Ваше решение: подтверждают!

# Рефакторинг №-7: «`prepare_html` и `prepare_pdf` — копипаста обвязки»

Описание проблемы:
В `workspace/actions.rs` два метода отличаются статусной строкой, вызовом `deck_gen::prepare_*` и текстом успеха. Общее: guard `loading`, `TimeoutFuture(0)`, `Arc<VfsFs>`, `take_vfs`, warning. Это не разная бизнес-логика, а дублированная оркестрация.

Предлагаемое решение:
Один приватный хелпер `run_prepare(status, warning, |fs| …)` с generic/`async` замыканием. Сами вызовы `prepare_html` / `prepare_pdf` не трогать.

Ожидаемый эффект:
Меньше расхождения при следующем изменении обвязки; код короче.

Ваше решение: неподтверждаю!

# Рефакторинг №-8: «Один и тот же паттерн async-действия с `loading` + warning»

# Рефакторинг №-9: «Классификация расширений размазана по 4 модулям»

Описание проблемы:
Один и тот же вопрос «что за файл?» решается заново:
- `load_folder/policy.rs` — import allow-list + `is_image`;
- `workspace/split.rs` — `is_previewable`;
- `ui/windows/editor/preview.rs` — match ext + `image_mime`;
- `ui/windows/editor/highlight.rs` — `syntax_name_for_ext`;
- `ui/icons/files.rs` — `icon_kind`.
Списки jpg/png/ico/html/md частично дублируют `conf::import`, частично нет (preview знает `htm`/`markdown`, import — нет). Это не баг логики, а три точки правки при новом типе.

Предлагаемое решение:
Один модуль (например `fs/kind.rs` или `conf` + тонкий `file_kind`) с enum вроде Text/Markdown/Html/Json/Scss/Pdf/Image/Other и предикатами `is_image` / `is_previewable` / mime / icon / highlight grammar. Списки расширений — только в `conf.rs`. Поведение предикатов сохранить 1:1 (включая расхождения import vs preview, если вы их подтвердите).

Ожидаемый эффект:
Новый тип файла правится в одном месте; меньше риска, что иконка есть, а preview нет.

Ваше решение: подтверждают!

# Рефакторинг №-12: «`PickResult` и `PickFilesResult` — почти один enum»

Описание проблемы:
Два enum с одинаковыми `Cancelled` / `Rejected(String)` / `Ready { files, … }`. Различие — поля `name`+`dirs` у папки. Обработка в picker (`finish_collect` / `finish_collect_from_list` / `finish_entries`) тоже тройная обёртка над одним match.

Предлагаемое решение:
`enum PickOutcome<T> { Cancelled, Rejected(String), Ready(T) }` плюс две структуры payload. Свести finish_* к одной функции. Политику reject не менять.

Ожидаемый эффект:
Проще сопровождать импорт; меньше ветвлений.

Ваше решение: подтверждают!

# Рефакторинг №-16: «Эксплорер на каждый кадр заново строит Vec строк и клонирует имена»

Описание проблемы:
`flatten_tree` обходит VFS; `children()` каждый раз выделяет `Vec<(String, bool)>` с `name.clone()`. Потом ещё `path.clone()` в `TreeRow` и 4 clone path в замыканиях ряда. `row_looks_selected` на **каждый** ряд поднимается по родителям и для каждого уровня делает `parent_path` → новая `String`. При открытом дереве monopoly это лишняя работа на каждый click/keystroke (если сигнал vfs/expanded/selection дёрнулся).

Предлагаемое решение:
`children` отдавать итератором/`&str`; `parent_path` — `&str` через `rsplit_once` без alloc (owned — только join). Для selected: хранить prefix-set или проверять `path == sel || path.starts_with(sel + "/")` без цикла alloc. Ряды: меньше clone в `For` (взять `Rc<str>` для path или один clone на ряд).

Ожидаемый эффект:
Легче клики по дереву и меньше GC-подобных пауз в WASM.

Ваше решение: подтверждают!

# Рефакторинг №-18: «Кастомный парсер iframe в preview — оставить, но убрать лишние lowercase всего документа»

Ожидаемый эффект:
Дешевле открытие `preview.html` с несколькими iframe.

# Рефакторинг №-20: «Параллелизация CPU в WASM — не делать»

Описание проблемы:

# Что сознательно не предлагается

- Менять алгоритмы copy/paste, unique_name, GitHub-фильтр путей, политику «весь импорт reject при одном плохом файле».
- Объединять VFS с `deck_gen` (вне разрешённого крейта).
- Выкидывать syntect / IndexedDB / split-preview — это фичи, не пустые абстракции.
- `OnceLock<SyntaxSet>` и `conf.rs` как единая точка констант — уже в хорошем состоянии.
- Комментарии-шапки модулей в целом уже соответствуют правилам.

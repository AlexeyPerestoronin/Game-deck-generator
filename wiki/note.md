# Заметки по этапу реализации «change width of fs tree»

## Пост-действия, которые требуются от пользователя (после этого сеанса)
1. Ручная приёмка в браузере (обязательно, т.к. drag — интерактивная UI-фича):
   - `cd deck_gen_wasm`
   - `trunk serve`
   - Открыть http://localhost:8080 (или порт по умолчанию)
   - Потянуть за узкую полоску между панелью проводника (слева от editor) и редактором:
     * Проверить, что ширина меняется плавно.
     * Довести до 0 — дерево полностью исчезает, но остаётся 4px resizer с pill-грипом при hover, можно потянуть обратно.
     * Довести до максимума (~половина оставшегося места после 48px activity bar).
     * Убедиться, что activity bar и содержимое editor (в т.ч. split) не пострадали.
     * Проверить на разных размерах окна.
   - Сообщить, если есть регрессии (редко, т.к. правки только в layout .ide).

2. После успешной ручной приёмки этапа-1:
   - Согласно "Дополнительные указания" в плане, код можно отрефакторить по `wiki/prompts/refactoring-rules.md`.
   - Текущая реализация намеренно минималистична и "прямолинейна" (всё в LoadedApp, без доп. абстракций), чтобы соответствовать "Изменения в коде должны быть минимальными!" и "этап-1".

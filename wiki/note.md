# Заметки по задаче «progress ray»

## Пост-действия, которые требуются от пользователя
1. Ручная приёмка в браузере (луч — визуальная UI-фича; в сессии нет browser automation):
   - `cd deck_gen_wasm`
   - `trunk serve`
   - Открыть http://localhost:8080
   - В покое: между activity bar и деревом файлов узкая (~10px) **зелёная** полоска на всю высоту.
   - Prepare HTML, Prepare PDF, New Game, Load Game, Download: полоска становится синей от центра к краям и к концу операции заполняется, затем снова зелёная.

   - Explorer по-прежнему ресайзится; максимум чуть уже из‑за колонки 10px.
   - Split Preview и Clear луч **не** запускают.
2. Если trunk ещё не установлен — `cargo install trunk`, target `wasm32-unknown-unknown`.

- Правки кнопок, explorer, editor, `deck_gen`.
- localization / themes / feedback (отдельные задачи этапа).

# Заметки по доработке №1 (`new_subprocess`)

## Пост-действия
1. Ручная проверка луча при Load files / Load Game / New Game: синий луч должен заметно расти **во время** копирования (особенно New Game: сначала fetch, потом запись файлов), не только прыжком в конце блока 90–100.
2. Остальное как в предыдущей заметке: `trunk serve`, http://localhost:8080.

## Ограничение
`install_files` / `install_folder` синхронные: браузер не перерисует кадр внутри их циклов (WASM однопоточен). Проценты в сигнал пишутся; кадр — на ближайшем `yield_frame` в `actions.rs`. `install_new_game` ждёт сеть в блоке 0–40, там луч успевает обновиться.

# Заметки по доработке №2 (ZIP progress)

## Пост-действия
1. Ручная проверка Download: луч должен заполнять первую половину пока собирается ZIP (много файлов — дольше encode), вторую — на save picker / скачивание.
2. Как раньше: `cd deck_gen_wasm && trunk serve`, http://localhost:8080.

## Ограничение
`vfs_to_zip` синхронный: пока архив пишется, кадр не отдаётся (как у `install_files`). Сигнал обновляется по записям; отрисовка — после блока 0–50, на `yield_frame`. `save_zip_bytes` async (picker), там луч 50–100 может успеть показаться.

# Заметки по доработке №3 (не блокировать UI)

## Пост-действия
1. Ручная проверка: `cd deck_gen_wasm && trunk serve`, http://localhost:8080.
2. Download / Load Game / New Game / load files: луч должен **шагать по файлам**, UI (кнопки, дерево) не «замирает намертво» на всё время операции.
3. Prepare HTML/PDF: луч 0→10, затем пауза на весь вызов движка (его нельзя нарезать без `deck_gen`), затем 90→100.

## Почему не отдельный OS-поток
В `wasm32` нет `std::thread`; Worker не видит DOM (`prepare_pdf`). Вместо потока: `spawn_local` + `TimeoutFuture(0)` после каждого `progress.set`. Это единственный способ, чтобы браузер успел нарисовать луч.

# Пост-действия (требуются от пользователя)

После применения изменений по todo.md:

1. Ручная проверка в браузере (обязательно, т.к. unit-тесты не заменяют реальный File Picker):
   - `serve.bat` (или `trunk serve`)
   - Открыть http://127.0.0.1:8080
   - "Load Game" → выбрать папку, внутри которой есть .js (например, скопировать fit-header-name.js в games/new-game/views/)
   - Проверить, что .js загрузился, виден в дереве explorer, открывается в редакторе как текст.
   - Отдельно: кнопка загрузки отдельных файлов → выбрать .js напрямую.
   - Проверить отклонение: .txt или .pdf всё ещё блокируется с правильным сообщением.
   - Проверить на desktop и (если есть) mobile viewport.

2. Если нужно полноценно поддерживать .js (подсветка синтаксиса, иконка в explorer, preview):
   - Потребуется правка вне разрешённых sub-крайтов (deck_gen_wasm/fs/file_kind.rs: kind_of, syntax_name, explorer_icon и тесты).
   - Сейчас .js импортируется как обычный текст (FileKind::Other), редактируется, сохраняется — этого достаточно для задачи.

3. Полная проверка workspace (опционально, т.к. инструкция требовала только локальные тесты изменённых крейтов):
   - cargo test -p deck_gen_wasm_fs   (должен пройти, т.к. мы не добавили негативных ассертов на .js)
   - cargo check -p deck_gen_wasm (или trunk build)

4. Зафиксировать изменения git'ом:
   - git add deck_gen_wasm/conf/src/api.rs deck_gen_wasm/import/... wiki/result.md wiki/note.md
   - (опционально) git add wiki/todo.md с отметкой выполненной задачи.

5. Если в будущем будут добавляться другие текстовые типы (например .ts, .rs в views) — достаточно одной строки в IMPORT_TEXT + тест.

Никаких других действий не требуется. Изменения минимальны и изолированы.

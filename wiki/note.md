# Пост-действия после доработки №3 (Rearrange)

Теперь drag использует нативный ghost + live reorder в on:dragover.

Когда водишь прозрачным клоном над другими вкладками — реальные вкладки перестраиваются (live), поэтому при отпускании мыши порядок уже новый.

## Обязательная проверка
- Запусти приложение.
- Начни drag вкладки (должен появиться ghost-клон).
- Перемещай ghost над другими вкладками внутри той же панели — наблюдай, как реальные вкладки меняют порядок "под" ним.
- Отпусти — порядок должен остаться в позиции, которую ты выбрал ghost'ом.
- Проверь split (отдельные панели).
- Close All, клики, активация не должны ломаться.

Если всё ещё не фиксируется — укажи, в каких именно ситуациях (drag на себя, на соседнюю, далеко и т.д.), и в каких браузерах.

# Пост-действия после доработки №2 (Rearrange)

Предыдущие правки (user-select, document listeners, prevent/stop, pointer-based) не помогли — reorder по-прежнему не происходил.

Решение: полностью заменили механизм запуска drag на декларативные `on:drag*` leptos-события (нативный DnD). 
- dragged состояние через StoredValue (без dataTransfer, чтобы не зависеть от фич web_sys).
- target вкладка известна автоматически в on:drop (обработчик "живёт" на элементе вкладки).
- before/after по clientX относительно rect цели.

Это должно решить проблему "слушатели не срабатывают" из-за особенностей event handling в Leptos-приложении.

## Обязательная проверка в браузере
- Перезапустите приложение.
- Убедитесь, что drag вкладок теперь работает (зажать и потянуть внутри одной полосы → визуальный reorder).
- Проверьте split / non-split.
- Close All по-прежнему должен работать.
- Нет регрессий по активации/закрытию/открытию вкладок.

Если и это не сработает — нужны более детальные наблюдения (console, какие события приходят, инспекция DOM во время попытки drag).

# Пост-действия после доработки №1 (Rearrange)

## Что было исправлено
- Drag не работал из-за возможного вмешательства text-selection + attach listeners к window вместо document + отсутствие preventDefault в mousemove.

- Переключены addEventListener на document.
- Добавлены stop_propagation + preventDefault в mousemove.
- Close all по-прежнему работает.

  - Проверить в split (левая и правая полосы независимо).
  - После reorder: клики, активация, close, split toggle должны работать.
- Убедись, что нет неожиданного выделения текста при попытке drag.
- Протестировать в Firefox и Edge (как раньше).

# Пост-действия после button_annotations

## Обязательная ручная проверка в браузере (по общим правилам проекта для UI-изменений + приёмке задачи)
- Запусти дев-сервер для WASM UI (обычно `trunk serve` из корня или `serve.bat` / `start.bat`).
- Открой приложение в браузере.
- Убедись, что слева есть activity bar с 7 кнопками (New game, Load game, Download, Prepare HTML, Prepare PDF, Split preview, Clear).
- Для **каждой** из 7 кнопок:
  - Наведи курсор и удержи неподвижно > 1.5 секунды.
  - Должен появиться DelayedTooltip с **точным** текстом, который был до изменений (см. строки в conf/src/api.rs).
  - Тултип исчезает при уходе курсора.
- Проверь в desktop viewport. (Mobile не обязателен для activity bar.)
- Убедись в отсутствии регрессий:
  - Кнопки работают (клик запускает те же действия).
  - Нет лишних тултипов.
  - Другие элементы (в explorer header NewFile/NewFolder) по-прежнему используют только title=, без delayed tooltip.

## Возможные доработки (только если проверка покажет проблему)
- Если текст тултипа не совпадает — проверить, что const в conf/src/api.rs и text=conf::ui::... в кнопке совпадают.
- Никаких изменений в CSS/логике не требуется по задаче.

## Дополнительно
- Полная визуальная/интеграционная проверка лежит на ручной проверке, т.к. правки только в строках (логика рендера tooltip'ов осталась нетронутой).
- После успешной hover-проверки можно коммитить.
- Сборка и unit-тесты уже зелёные: `cargo test -p deck_gen_wasm_conf -p deck_gen_wasm_ui`.

Дата: 2026-09-15

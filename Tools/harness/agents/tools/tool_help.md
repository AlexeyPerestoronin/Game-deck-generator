# Подробная справка по инструментам DefaultTools

Инструменты работают в песочнице. Доступ к путям ограничен списками `r`- и `w`-директорий; операции с файлами — списком допустимых расширений. Shell-команды ограничены белым списком. Списки допустимых путей, расширений и команд можно получить через `list_available_*`. Перед записью или запуском команд проверяйте, что путь и команда разрешены.

---

## read_file

Прочитать содержимое текстового файла.

**Параметры:**
- `path` (string, обязательный) — путь к файлу.

**Поведение:**
- Нужен `r`-доступ к расположению файла.
- Расширение файла должно быть в списке допустимых.
- Файл читается целиком в кодировке UTF-8.

**Возвращает:** содержимое файла.

**Ошибки:** `cannot read file '<path>' → ...` (нет доступа, недопустимое расширение, файл не найден и т.п.).

**Пример:**
- вызов: `read_file(path="Tools/harness/logger.py")`
- результат: исходный текст файла.

---

## write_file

Записать текстовый файл (создать или полностью перезаписать).

**Параметры:**
- `path` (string, обязательный) — путь к файлу.
- `content` (string, обязательный) — новое содержимое.

**Поведение:**
- Нужен `w`-доступ; расширение должно быть допустимым.
- Родительские каталоги создаются автоматически.
- Существующий файл перезаписывается целиком.

**Возвращает:** `success: wrote <path>`

**Ошибки:** `cannot write file '<path>' → ...`

**Пример:**
- вызов: `write_file(path="Tools/harness/notes.md", content="# Notes\n")`
- результат: `success: wrote Tools/harness/notes.md`

---

## apply_diff_patch

Применить unified-diff патч к существующему файлу через `git apply`.

**Параметры:**
- `path` (string, обязательный) — целевой файл.
- `patch` (string, обязательный) — патч в формате unified diff.

**Поведение:**
- Нужен `w`-доступ. Расширение файла не проверяется.
- Заголовки `diff --git`, `---`, `+++` переписываются на имя целевого файла. Заголовки `/dev/null` сохраняются.
- Если заголовков нет, они добавляются автоматически.
- Ханки должны точно соответствовать текущему содержимому файла.

**Возвращает:** `success: patched <path>`

**Ошибки:** отказ в доступе либо ошибка `git apply`, если патч не применяется.

**Пример:**
- вызов:
  `apply_diff_patch(path="app.py", patch="@@ -1,3 +1,3 @@\n print('a')\n-print('b')\n+print('c')\n print('d')\n")`
- результат: `success: patched app.py`

## get_file_diff

Получить unified-diff целевого файла относительно `HEAD` через `git diff`.

**Параметры:**
- `path` (string, обязательный) — целевой файл.

**Поведение:**
- Нужен `r`-доступ. Расширение файла не проверяется.
- Выполняется `git diff HEAD -- <файл>` в каталоге файла (как `apply_diff_patch` вызывает `git apply`).
- Возвращается unified diff, совместимый с `apply_diff_patch`.
- Нетракнутые файлы и отсутствие изменений дают пустую строку.

**Возвращает:** текст diff либо пустую строку, если изменений нет.

**Ошибки:** отказ в доступе либо ошибка `git diff`.

**Пример:**
- вызов: `get_file_diff(path="app.py")`
- результат:
  ```
  diff --git a/app.py b/app.py
  index 1111111..2222222 100644
  --- a/app.py
  +++ b/app.py
  @@ -1,3 +1,3 @@
   print('a')
  -print('b')
  +print('c')
   print('d')
  ```

## create_file

Создать пустой файл.

**Параметры:**
- `path` (string, обязательный) — путь к файлу.

**Поведение:**
- Нужен `w`-доступ и допустимое расширение.
- Родительские каталоги **не** создаются (в отличие от `write_file`).
- Если файл уже существует, он будет очищен.

**Возвращает:** `success: created <path>`

**Ошибки:** `cannot create file '<path>' → ...`

**Пример:**
- вызов: `create_file(path="Tools/harness/tmp.py")`
- результат: `success: created Tools/harness/tmp.py`

## remove_file

Удалить файл.

**Параметры:**
- `path` (string, обязательный) — путь к файлу.

**Поведение:**
- Нужен `w`-доступ. Расширение не проверяется.
- Удаляется только файл, не каталог.

**Возвращает:** `success: removed <path>`

**Ошибки:** `cannot remove file '<path>' → ...`

**Пример:**
- вызов: `remove_file(path="Tools/harness/tmp.py")`
- результат: `success: removed Tools/harness/tmp.py`

## move_file

Переместить или переименовать файл.

**Параметры:**
- `src` (string, обязательный) — исходный путь.
- `dst` (string, обязательный) — путь назначения.

**Поведение:**
- Для `src` и `dst` нужны `w`-доступ и допустимые расширения.

**Возвращает:** `success: moved <src> to <dst>`

**Ошибки:** `cannot move file ...`

**Пример:**
- вызов: `move_file(src="Tools/a.py", dst="Tools/b.py")`
- результат: `success: moved Tools/a.py to Tools/b.py`

## list_folder

Вернуть содержимое директории на заданную глубину обхода.

**Параметры:**
- `path` (string, обязательный) — путь к директории.
- `depth` (string, обязательный) — глубина обхода (целое число строкой).

**Поведение:**
- Нужен `r`-доступ. `depth` преобразуется в `int`.
- При `depth > 0` сначала перечисляются подкаталоги (рекурсия с `depth - 1`), затем файлы текущего уровня; имена сортируются.
- `depth = "0"` — пустой результат (обход не выполняется).
- `depth = "1"` — только непосредственное содержимое `path`.
- `depth = "2"` — содержимое `path` и один вложенный уровень.

**Возвращает:** пути по одному на строку; пустая строка, если записей нет.

**Ошибки:** `cannot list folder '<path>' → ...`

**Пример:**
- вызов: `list_folder(path="Tools/harness", depth="1")`
- результат:
  ```
  Tools/harness/agents
  Tools/harness/__init__.py
  Tools/harness/agent_loop.py
  Tools/harness/logger.py
  ```

## list_available_r_dir

Показать директории с правом чтения.

**Параметры:** нет.

**Поведение:**
- Возвращает список `r`-директорий (включая `w`, т.к. запись подразумевает чтение).

**Возвращает:** `available: [<пути>]`

**Пример:**
- вызов: `list_available_r_dir()`

## run_shell

Запустить разрешенную shell-команду в указанном рабочем каталоге.

**Параметры:**
- `cwd` (string, обязательный) — рабочий каталог.
- `command` (string, обязательный) — имя команды без аргументов.
- `arguments` (string) — аргументы командной строки; передавать всегда, допустима пустая строка.

**Поведение:**
- `command` должна быть в списке `list_available_shell_commands`.
- Для команд из `w`-списка нужен `w`-доступ к `cwd`, иначе — `r`-доступ.
- Выполняется строка `command + " " + arguments` (`shell=True`).
- Лимит времени задается настройкой `command-execution-limit` (по умолчанию 60 с).
- Вывод декодируется как `utf-8`, затем `oem`, затем `cp1251`.

**Возвращает:** вывод команды либо `(command finished without output)`.

**Ошибки:**
- команда не в белом списке;
- отказ в доступе к `cwd`;
- таймаут: `execution of the '<cmd>' exceed the limit ...`.

**Пример:**
- вызов: `run_shell(cwd="Tools", command="python", arguments="-c \"print(1)\"")`
- результат: `1`
